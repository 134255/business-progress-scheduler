## 必测场景

1. **显示与输入**：模板节点名称、短文本、长文本地址、数字、日期、单选/级联、多选。逐字中文输入、拼音候选尚未确认、粘贴、换行、删除、清空、输入字面文本 `true`；反复切换焦点后其他字段不丢失。小屏、大字设置、键盘弹出/收起、页面滚动、桌面窗口缩放时当前输入可见、不被裁剪，控件不重叠。只读与编辑状态符合角色。
2. **联动**：变更父单选后，正确展示下游字段及候选；有值清理须确认，取消保留全部原值；隐藏字段不能误清空无关字段。
3. **选择入口**：分别测试图片、视频和 PDF。明确记录实际出现相册、本机文件窗口还是聊天会话选择；不能仅记录“接口调用成功”。重点复现 Mac 误跳聊天列表、列表为空、文件灰色不可选，以及移动端本机文件来源是否可达。
4. **异常恢复**：取消选择、空列表、权限拒绝、接口不支持、临时路径不可读；不得清空已填字段或已有附件，非取消失败应有可理解提示，不能静默或一直锁定。系统隐私授权由用户本人操作，不自动放宽权限。
5. **格式与路径**：用合成无隐私样本检查 JPG/JPEG/PNG/WebP/HEIC/HEIF、PDF、MP4/MOV/M4V（遵守当前节点白名单）；大写后缀、中文/空格文件名、系统返回临时路径、相机新拍与本地已有文件。真实格式与后缀不符仍须拒绝，不以取消安全校验掩盖兼容问题。上传支持与本机预览解码支持分别记录。
6. **大小与网络边界**：小文件、超过 90 MiB 的视频、单个 120 MiB、多文件合计 120 MiB、合计超出 1 字节。只执行现有 120 MiB 总量规则；检查断网重试、部分成功后重试不重复、慢速凭据刷新、前后台切换与进度不倒退。真实传输不能用 mock 的 120 MiB 元数据冒充。
7. **提交可靠性**：已登记附件不重传；提交等待分阶段清晰；弱网/响应丢失按权威状态恢复，不误报成功或失败；失败后字段和附件保留，重复操作不产生重复审核。提交成功后重新进入核对记录。

## 2026-09-08 审计发现（历史基线）

下列代码行号和缺口记录的是 1.0.11 基线；选择器能力/失败处理及桌面错误分流已在上节本地修正，体验版及真机状态尚未更新。

- `miniprogram/pages/node-feedback/index.js:173` 仅按 `mac/windows` 分流，其他或无法识别的平台走移动媒体接口；没有选择器能力探测。
- 同文件 `631`、`663` 的媒体与 PDF 选择路径只有 `success`，无应用层 `fail` 处理或 API 缺失保护。取消与非取消错误未区分；接口拒绝可能没有应用提示。
- 桌面媒体和各端 PDF 均使用 `chooseMessageFile`。微信官方 [API 类型源码](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts) 将其描述为从客户端会话选择文件；这不是所有桌面版本均可打开本地文件夹的证据。官方 HTML 文档本次无法读取，已以官方源码交叉检查，不推断未记录的端能力。
- `node-feedback-v2.test.js` 的 Mac 测试名称虽写“本地文件选择器”，实际只 mock 接口及返回值，不能当作真实系统窗口验收。
