# 数据模型（MVP）

## 核心集合

| 集合 | 用途 | 关键字段 |
|---|---|---|
| users | 小程序用户档案 | openid、displayName、status |
| business_lines | 业务线主表 | name、code、status、managerIds、memberIds、currentNodeIndex、progress |
| business_nodes | 业务节点 | businessLineId、sequence、status、assigneeIds、requiresEvidence |
| node_feedback | 节点反馈历史 | nodeId、status、comment、evidenceIds、submittedBy |
| evidences | 凭证元数据 | fileId、fileName、mimeType、size、uploadedBy |
| templates | 业务模板主表 | name、managerIds、status、version |
| template_nodes | 模板节点 | templateId、sequence、name、默认配置 |
| invitations | 业务邀请 | token、businessLineId、nodeId、role、expiresAt、status |
| notifications | 待发送通知 | recipientId、type、status、businessLineId、nodeId |
| audit_logs | 审计记录 | actor、action、targetType、targetId、snapshot |

## 权限原则

客户端不直接执行关键写操作，统一调用 `businessApi` 云函数。云函数从微信上下文获取 OpenID，并执行以下规则：

1. 业务线管理员：编辑、配置成员、配置节点、删除业务线、查看全部凭证。
2. 节点负责人：查看业务线并反馈绑定节点；完成强制凭证节点时必须上传凭证。
3. 普通关联成员：只读业务线、节点和有权查看的凭证。
4. 删除为逻辑删除，保留审计记录；永久清理由后续定时任务按保留策略执行。

## 推荐索引

- `business_lines.code`：唯一业务编号（应用层先校验；生产环境需配合唯一性治理）。
- `business_lines.memberIds + updatedAt`：成员业务列表。
- `business_nodes.businessLineId + sequence`：节点时间线。
- `business_nodes.assigneeIds + status`：待办列表。
- `node_feedback.nodeId + createdAt`：反馈历史。
- `evidences.businessLineId + nodeId + createdAt`：凭证查询。
- `invitations.token + status`：邀请接受。
