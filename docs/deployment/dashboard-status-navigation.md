# 概览状态卡跳转修复部署与验收

## 范围

首页“进行中”和“已完成”进入售后列表，并携带对应 `status` 与 `scope=mine`。列表显示“与我相关 · 进行中/已完成”，在普通翻页和关键词检索中保留状态及关系范围。“查看全部”保持旧入口：普通成员只见原授权范围，活动超级管理员可查看全部。

首页统计本来按成员/管理员关系统计，因此卡片使用 `mine`。未扩大权限，也不改历史数据。首页存在 2,000 条安全扫描边界，超大账号的卡片可能为下界，不能以卡片数字当作无限规模下的精确总数。

## 发布顺序

1. 上传完整 `cloudfunctions/businessSearch`，保留现有密钥、环境变量、触发器、运行配置与权限。
2. 上传完整 `cloudfunctions/businessApi`，保留现有配置。必须包含 `lib` 及依赖，不能只传 `index.js`。
3. 两个云函数运行正常后，再编译、上传包含本次修改的小程序体验版。

原因：旧 API 会拒绝新的 status/scope 查询参数，旧检索工作器可能忽略它们。不可先发布新客户端，避免错误提示或展示未筛选结果。无筛选的旧客户端继续使用原合同；本次无需新增集合、索引或权限。

当前本地修复、测试结果和实际是否部署，以 `docs/memory/STATUS.md` 最新条目为准。没有云端和真机证据时，不标记发布完成。

### 2026-09-10 入口白名单补漏

状态筛选必须同时通过 `businessApi/index.js` 的 `createBusinessRoutes/listBusinessLines` 白名单，不能只修改服务层。入口允许 `status`、`scope` 后仍由服务严格限制枚举、由仓储重验权限；测试必须经过真实 API 入口，不能只用页面服务桩或直接调用查询服务。

本次先备份已部署代码，确认 59 个生产及包文件中仅入口存在一行预期差异，其余库与依赖完整且逐项一致，因此使用官方 CLI 对 `index.js` 做单文件增量更新。该例外不替代首次发布的完整部署要求；文件不完整、版本不一致或依赖变化时不得照搬。更新后回下载 59/59 核验，并在当前开发者工具连接真实云端验证两张卡自动显示对应列表；无需重新上传现有客户端。其他设备验收范围仍以 STATUS 为准。

## 验收

- 普通成员分别点击“进行中”“已完成”的数字、文字与卡片空白处，均进入对应列表。
- 列表中的每条售后状态符合入口；不能仅以某个节点完成作为整条售后完成。
- 超管卡片只显示与当前账号有关的售后；“查看全部”仍可查看所有售后。
- 翻到第二页、输入关键词、改变日期及清空关键词，状态和关系筛选不丢失。
- 返回详情再回到列表，及返回首页再切换另一状态，无错误跳转或交叉结果。
- 没有结果时显示空提示；搜索候选空页但仍可续查时显示“加载更多”，不误报无结果。
- 在读取期间切换账号、停用账号、撤销关系或更改售后状态，不展示失效结果；不同状态/范围的搜索游标不能互用。

使用专用无隐私验收数据。不要为了验收修改正在使用的真实售后、客户字段或账号权限。

## 回滚

优先回退客户端，或隐藏新增状态入口；新后端兼容旧无筛选客户端，可保持运行。若必须回退后端，先确认新客户端入口已退出使用，避免仍发送新参数；不要删除集合、调整权限或覆盖既有环境变量。
