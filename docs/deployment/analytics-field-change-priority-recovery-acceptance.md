# 字段统计变更优先恢复：本地验收与净成本

2026-11-09。本文件不是发布回执或云费用报价。本次仅本地实现/测试，未提交、推送、部署、创建集合、改变量/Timer/权限或发送消息。

## 实现与兼容边界

保留业务提交后原即时字段刷新；新增独立、尽力而为的服务端售后级队列。登记失败不撤销原业务成功，也不阻止原即时刷新。队列使用随机代际、revision CAS、持久待确认清单和有界轮转；旧确认不能清理新代际，中途退出不会丢未确认编号。队列只是提示，恢复仍重读当前节点、售后、反馈、审核轮、投票并在发布事务重验。

字段阶段共享原40候选/5000ms协作预算；完整巡检运行时先分配最多8条，队列每轮最多8工作项、每项最多8节点。每售后100节点/50票边界不扩大。完整巡检真正到尾并通过游标版本及巡检代际校验，才从完成时刻起等待60分钟；不是“一小时修复完成”的承诺，触发间隔/分页/积压/异常另计。

API `OPERATIONS_FIELD_CHANGE_QUEUE_ENABLED` 仅精确true启用登记；worker `OPERATIONS_FIELD_RECOVERY_MODE` 仅priority-repair选择新模式，缺省/legacy仍旧模式。实际云变量未改。未新增客户端操作、公开action、依赖或业务写事务；售后内容/进度、通知、账号、工时统计和企微规则保持，现有客户端源码逐字节未改。

## 净成本方法

原/新使用同一合成初态、变化序列和虚拟时钟，运行准确前像/候选的真实统计handler；原工时阶段、原即时刷新、新队列登记/发现/领取/确认、巡检控制全部计入。API变化测试仅在已成功提交的边界注入合成源变化，再运行真实内部信号与原字段仓储，不把合成扰动说成真实业务提交或允许修改终稿。

30组：6种历史/状态×1/5/15分钟的完整24小时，共18组；单次/30次集中/持续变化/漏登记4组；15分钟另补6组100调用（25小时，不冒充24小时）；实际队列SDK写失败1组，以及1个节点每分钟持续变化的反例1组。每组保留1/10/100调用检查点（24小时15分钟仅96调用，由补充组覆盖100），阶段/集合拆分、首次开销、返回文档和字节、写尝试/成功回执及事务回调/失败。原/新受保护数据hash及最终快照一致，未解决目标均0；不是逐时点统计完全相同。

准确最终结果：QA目录 `cost-final-full.json`（complete:true,22组）、`cost-final-supplement.json`（complete:true,8组）、`cost-final-summary.json`（complete:true,30组）、`preread-probe.json`；两轮命令均exit0，最终分析还逐项确认全部报告的确认写数等于fake实际提交写数。修复前29组结果也保留，不将旧源码测量冒充修复后结果。字节是合成JSON响应大小，不是压缩流量或数据库实际计费字节。容量fake仅在内存用浅Map快照替代原深拷贝，回滚/冲突/拷贝语义及完整handler操作与原fake交叉一致；测试工具变快不代表线上响应变快。

不能只取稳定空闲段：30个完成/审核完成场景首次都多5get、2query、2set、2事务；累计数据操作观察到第2调用才首次不高于原版。150节点在15分钟/100调用补充组到第5调用；2000节点同组第52调用才首次抵消，并不代表现金回本。完全空库整个观察期未抵消：三种频率全天均额外168数据操作、48写/事务；1/5/15分钟对应数据操作增1.17%/5.83%/17.5%。2000历史、15分钟触发的24小时仅下降1.78%，query反而2380→2505；大积压不能宣传同样高收益。

高频小数据反例也更贵：仅1个审核完成节点、每分钟持续变更24小时，原60461→新78196数据操作（增29.33%），事务4319→10169、写尝试5757→11584、JSON响应45514134→53067115字节。不能把30历史节点场景的收益套到每个工作负载，必须在上线前核实实际历史规模/变更频率和资源计价。

漏登记且无即时刷新场景在5分钟虚拟触发下观察到55分钟修复等待；正常即时刷新场景本样本为0分钟，均不是线上SLA。全矩阵最大单事务9操作；50票极限由原来源恢复边界测试另覆盖，不以这个小值代替上限。强制第二节点固定读跨过5秒的预读探针：原/新都返回4份反馈预读，仅1份消费，3份未用；原9get/3query/3set/3事务，新11/4/4/4，所有未用响应和新增控制开销已计入；到期后新SDK请求0。

## 上线前仍需另行确认

结论是本地成熟历史场景净操作收益成立，不是已验证整张云账单降幅。原API计费映射、真实读/写/计算/日志/存储/流量、当前实际Timer和历史规模均未联云核实；空库与大积压存在反例，暂不无条件推荐全量开启。

后续获授权才可：先备份准确云包/配置，核对私有集合及客户端拒绝策略、现有索引计划和运行时能力；明确新增队列/控制文档存储及按量读写/事务/日志等费用，再最小发布两个函数并小流量开启开关、验证真实运行和账单。不得自动扩IAM、购买资源、改Timer或启用其他降本项。回退仅关闭API登记并将worker切回legacy，保留队列/原游标/快照和备份，不删业务数据；原即时刷新一直保留。
