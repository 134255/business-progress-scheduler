### Windows 官方 CLI 打包注意

当前安装版完整目录 `deploy` 路径经实际内置 ZIP 库复现会保留反斜杠，不能仅凭上传成功断言 Linux 下模块可加载。现有函数优先在核对云端已安装依赖和锁文件一致、备份当前代码后，使用 `cloud functions inc-deploy --name <函数名> --file . --env <目标环境> --project <正确项目>` 上传完整目录；该目录分支显式把路径规范化为 `/`，不删除旧文件或安装依赖。不应只增量上传 `index.js`，也不能用尚未包含脏修复的 `git archive HEAD` 打包。

这次 businessSearch 先云端安装固定依赖，再使用上述完整增量接口补齐；businessApi 既有三项固定依赖与锁文件均匹配，备份后完整增量更新。回下载哈希可核对文件字节，但 Windows 解压会合并不同斜杠方向，因此必须同时验证实际函数调用。涉及新依赖时，应另行采用规范化 ZIP 或经验证的构建方式安装依赖，不盲用增量替代依赖安装。

## 历史索引恢复不能省略

- 发布代码本身不会重建全部历史索引。`searchIndexStatus: pending` 可由既有受保护恢复流程重建，但本次未擅自启用 Timer。
- 旧代码曾遗漏说明/附件、但已经标为 `generated` 的代际，会被 `isGenerationCurrent` 视为当前；只部署或处理 pending 不能修复这些已就绪但不完整的代际。
- 下一步先只读统计目标环境的索引状态、来源版本与已生成版本，核对函数错误分类和现有组合索引；不导出关键词、字段内容、身份或凭证路径。
- 需要受控重建时应明确目标范围、备份/恢复与读取写入预算。不能为了让搜索命中而伪造业务反馈、反复提交审核、删除售后、直接篡改字段或自动开启无界扫描。费用或安全权限变化仍需项目所有者确认。
- 日志登录、部署和修复后代际均核实前，不宣称线上问题已经解决。

## 验收矩阵（使用无敏感测试售后）

1. 使用单个汉字、完整字段值、多个关键词分别检索；同时验证名称/编号。返回命中字段/节点摘要，不返回无权限售后。
2. 可选字段留空、当前进度说明、重复保存后仍有效附件名均可检索；已被替换的字段、说明及旧驳回轮内容不可命中。
3. 受阻、已批准等待人工分支、无审核完成等待人工分支、驳回后尚未重新保存均可正常生成完整当前索引。
4. iOS 与 HarmonyOS 各测试逐字输入、粘贴、键盘确认及直接点检索；条件改变时旧列表消失，失败显示持久错误而不是全部售后或“无匹配”。
5. 查询中修改关键词/日期、后台切换后返回、快速先后查询、分页失败重试；不锁死加载、不混用游标、不显示旧账号响应。
6. 从首页进行中/已完成进入时保持原状态及关联范围；无参“查看全部”保持既有权限。真机录屏须避开客户信息与凭据。
