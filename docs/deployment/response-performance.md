# 响应速度优化与验收

## 范围与边界

本轮只优化既有流程：售后关系查询与候选重验有限并发、首页审核/通知单次受保护窗口统计、历史附件有限并发、检索代际写入与快照读取有限并发、计算内日历代际复用、上传预检同事务去重和客户端分段计时。

- 权限校验不跨请求缓存，不合并不同授权阶段的账号读取。
- 每组查询仍完整分页，候选仍重验后过滤、排序和分页；首页 2,000 条扫描边界与审核/通知 100 条窗口保持原含义，不把窗口计数称为全库总数。
- 并发池最多 4 项，结果保持输入顺序；失败后停止领取新项，并等待已经启动的任务结束后再向调用方报告失败。
- 检索内容及令牌全部写完才进入原发布事务；不去掉同步等待、不提前显示保存成功。来源版本、旧代竞争、幂等恢复与 100 次事务预算不放宽。
- 日历仅计算内复用，真正复用的代际在使用结果前复验；切换时有界重算，不同请求不共享缓存。
- 附件维持 3 文件并发、同对象短期授权刷新、真实大小/签名核验、120 MiB 合计和最终发布前重新授权。
- 不调整内存、超时、费用、密钥、权限、数据库索引或定时触发器；不靠写真实售后来压测。

审查发现的既有边界：保留期限已过、但仍为 `available` 且尚未实际清理的附件，其文件名可能仍参与当前快照索引；部署前备份也有相同行为。本轮不改变文件名元数据的检索保留语义，也不宣称它已按期限过滤。缺失、已清理、跨售后/节点及无效轮次附件的拒绝规则继续保留；文件本体访问与元数据检索应分开核验。

## 发布与回退

1. 使用官方微信开发者工具 CLI 下载目标环境的 `businessApi`、`businessSearch` 代码到独立本机临时目录。只备份代码包，不导出环境变量或客户数据。
2. 对 `index.js`、`lib`、`package.json` 和锁文件逐项比较 SHA-256。确认差异仅为本轮代码，入口和固定依赖不变，线上所有其他文件完整；不上传未确认的控制台编辑器草稿。
3. 本轮变更均位于两函数 `lib`，在上述核验成立时，先对 `businessSearch`、再对 `businessApi` 执行 `cloud functions inc-deploy --file lib`，保证新增并发 helper 与调用方同批发送。不要只传一个调用方文件。
4. 分别再次下载并校验全部生产/包文件。CLI 成功提示不能替代回下载和真实读接口验收。
5. 现有客户端可直接使用新后端。本地新增诊断仅在重新编译或发布包含它的小程序包后可用；上传体验版、切换体验版和真机写入验收需分别记录，不等同于云函数更新。

需回退时，从本轮备份中恢复这两个函数原 `lib` 代码，连同原入口/依赖核对一致性；不删除业务记录、检索代际、凭证对象或集合。旧调用方不引用新增并发 helper，遗留未引用 helper 不影响回退；不可为清理它扩大删除范围。回退同样要下载核验并复测。

## 脱敏计时

客户端诊断默认关闭，无持久化、日志上传或新增后端接口。在开发者工具当前小程序 JavaScript Console 中可显式开启：

```javascript
getApp().globalData.performanceDiagnostics = true
```

执行正常界面操作后，只查看安全计时数组：

```javascript
getApp().globalData.performanceTimings
```

数组最多保留最近 100 条，只包含白名单 `action`、可选 `stage`、`durationMs` 和 `OK/ERROR`。不含正文、账号/售后/节点编号、文件名、路径、凭据或错误消息。上传阶段为 `authorize`、`transfer`、`finalize`；传输阶段包含内部网络退避/续期，最终核验过期重试可能生成两个 finalize 样本。云调用和上传阶段有重叠，不能简单把所有样本相加当作整页耗时。

关闭并清空：

```javascript
getApp().globalData.performanceDiagnostics = false
delete getApp().globalData.performanceTimings
```

不要输出整个 `globalData`、云响应或上传会话。跨设备比较使用同版本、同账号权限、同数据、相近网络；记录接口与整页渲染的区别。真实创建/审核/上传采用用户正常业务操作，不自动反复创建或提交测试售后。

Computer Use 真实界面复测：从首页分别点击两张卡，空关键词/日期自动显示对应范围，页脚分别为已完成 6 条、进行中 16 条，与首页一致；进行中范围以通用关键词“售后”检索，结果和命中节点摘要正常展示。未保存响应正文、账号值或记录标识。

当前开发者工具已编译客户端的计时接线也已实测：显式开启后通过首页 `onShow` 记录一次 `getDashboardWorkspace`、4886 ms、OK，随后在 `finally` 关闭并清空内存计时。该次发生在 API 性能代码发布前，仅证明记录器接线，不计入更新后样本。手机上的新计时代码仍需发布相应客户端包；真实创建、保存/审核、上传分段和跨设备耗时均为 `unverified`，应使用用户正常业务操作验收，不制造业务记录。
