# 业务进度管理微信小程序技术落地规划

版本：V0.1（MVP 基线）  
规划日期：2026-08-03  
目标：在 8 周内完成可提交体验版并进入试运行的业务进度管理小程序。

## 1. 执行摘要

本项目采用“原生微信小程序 + 微信云开发 CloudBase + Node.js 云函数 + 云数据库 + 云存储”的一体化方案。第一阶段优先完成业务线、节点、成员、反馈、凭证、状态检索与权限控制的完整闭环；模板、邀请、订阅消息和审计能力在同一架构中预留并逐步启用。

关键原则：

- 所有关键写操作必须经过云函数，客户端不能自行修改业务状态或越权删除。
- 业务线管理员拥有业务线配置与逻辑删除权限；节点负责人只能反馈本人负责的节点；普通关联成员只读。
- 图片与 PDF 存储在云存储，数据库只保存受控的文件元数据和关联关系。
- 微信通知采用订阅消息机制；用户需主动授权，系统不能假设可以无限制、无感知推送。
- “拉入业务线”落地为邀请链接/二维码 + 被邀请用户确认加入，避免依赖不可获得的微信好友列表。

## 2. 产品目标与角色

### 2.1 产品目标

1. 让业务发起人快速定义一条包含多个顺序节点的业务线。
2. 让节点负责人清楚知道“当前轮到谁、要做什么、何时完成、需提交什么凭证”。
3. 让关联成员随时查看业务整体状态、节点历史与授权范围内的凭证。
4. 让高频业务流程沉淀为模板，降低重复配置成本。
5. 让管理人员按日期、名称和编号准确检索并追溯业务过程。

### 2.2 用户角色

- 业务线管理员：创建、编辑、配置节点、邀请成员、绑定负责人、查看全部数据、逻辑删除业务线。
- 节点负责人：查看关联业务、反馈本人节点状态、上传凭证。
- 关联查看者：查看业务线与节点进度，按权限查看凭证。
- 平台管理员（后续）：处理账号停用、数据恢复、审计与运营配置，不等同于业务线管理员。

一个用户可在不同业务线中拥有不同角色；权限以业务线维度计算。

## 3. 功能范围

### 3.1 MVP（首个可上线版本）

- 微信身份识别与用户档案初始化。
- 业务线创建、编辑、逻辑删除、详情查看。
- 动态配置节点名称、顺序、截止日期、是否强制凭证。
- 业务成员与节点负责人的邀请、加入和绑定。
- 节点状态：待开始、待处理、处理中、受阻、已完成。
- 节点反馈说明、反馈历史、图片/PDF 凭证上传与预览。
- 节点完成后激活下一节点，并生成待通知任务。
- 按计划日期、业务名称、业务编号检索。
- 将业务线保存为模板、从模板创建业务线。
- 权限校验、操作审计、错误日志与基础监控。

### 3.2 P1（试运行后增强）

- 节点审批/驳回与多人会签、或签策略。
- SLA 超时提醒、催办、升级通知与日历视图。
- 凭证版本、批量下载、在线水印与内容安全检测。
- 管理后台、组织架构同步、批量导入与统计报表。
- 业务线归档、恢复、数据保留周期与合规导出。

### 3.3 暂不纳入 MVP

- 任意复杂 BPMN 流程、条件分支和并行网关。
- 跨企业统一组织目录和复杂财务审批。
- 大规模全文检索引擎；MVP 使用受控字段检索与索引。

## 4. 核心业务流程

### 4.1 创建与启动

1. 管理员选择空白创建或业务模板。
2. 填写名称、唯一编号、说明、计划日期。
3. 配置节点顺序、负责人、截止日期和凭证要求。
4. 保存后第一个节点进入“待处理”，其余节点为“待开始”。
5. 系统向首节点负责人创建通知任务。

### 4.2 邀请与加入

1. 管理员生成带短期 token 的邀请链接或二维码。
2. 被邀请用户打开小程序并明确确认加入。
3. 云函数校验 token、有效期、目标业务线与预设角色。
4. 加入后写入业务成员和节点负责人关系，并记录审计日志。
5. 邀请 token 使用后失效；管理员可提前撤销。

### 4.3 节点反馈与流转

1. 负责人打开待办节点，选择“处理中 / 受阻 / 已完成”。
2. 填写说明并上传凭证；强制凭证节点在完成时必须至少有一个有效文件。
3. 云函数二次校验身份、节点状态、文件归属和版本号。
4. 保存反馈历史及凭证元数据。
5. 若节点完成，则激活下一节点；没有下一节点时业务线完成。
6. 为下一负责人生成订阅消息发送任务，并更新业务总体进度。

### 4.4 删除

只有该业务线管理员可删除。MVP 使用逻辑删除：列表隐藏但保留审计数据，避免误删后无法追溯；永久清理在数据保留期到期后由平台管理员或定时任务执行。

## 5. 技术架构

### 5.1 技术选型

- 客户端：原生微信小程序，WXML、WXSS、JavaScript（首版零构建依赖；通过 JSDoc/数据字典约束接口）。
- 后端：CloudBase Node.js 云函数，所有关键业务命令统一入口。
- 数据：CloudBase 文档型数据库。
- 文件：CloudBase 云存储，保存图片/PDF；数据库保存元数据和关联 ID。
- 身份：微信小程序 OpenID，后续可增加手机号或企业身份校验。
- 消息：微信订阅消息 + notifications 待发送队列。
- 监控：云函数日志、错误指标、审计日志与关键操作告警。

CloudBase 的小程序 SDK 已内置在微信小程序运行框架中，可直接访问数据库、云函数和云存储。对于本项目的复杂权限场景，客户端只负责展示和文件选择，业务写入由云函数完成。

### 5.2 分层结构

- 表现层：页面、组件、表单校验、状态展示、文件选择与预览。
- 客户端服务层：封装 `wx.cloud.callFunction` 与统一错误处理。
- 业务云函数层：身份识别、权限判断、状态机、事务/幂等、审计。
- 数据层：业务集合、索引、数据权限规则、软删除与版本号。
- 文件层：按业务线/节点组织云路径，使用 fileID 控制访问。
- 通知层：写入通知任务，发送成功/失败可追踪与重试。

## 6. 数据模型

### 6.1 核心集合

- `users`：openid、展示名、头像、状态、创建时间。
- `business_lines`：名称、编号、状态、管理员、成员、当前节点、进度、模板、计划日期、版本号。
- `business_nodes`：业务线 ID、顺序、状态、负责人、观察者、截止日期、凭证规则。
- `node_feedback`：节点、状态、说明、凭证 ID、提交人、提交时间。
- `evidences`：fileID、文件名、类型、大小、上传人、业务线与节点。
- `templates` / `template_nodes`：模板元数据和节点定义。
- `invitations`：邀请 token、目标业务线/节点、角色、有效期、状态。
- `notifications`：接收人、消息类型、关联业务、状态、重试次数。
- `audit_logs`：操作者、动作、对象、摘要、时间、请求标识。

### 6.2 状态机

业务线状态：草稿 → 进行中 ↔ 受阻 → 已完成；删除为独立终态。  
节点状态：待开始 → 待处理 → 处理中/受阻 → 已完成。

状态变化必须由云函数按允许的迁移关系执行。客户端上传的状态只是一项请求，不是最终可信结果。

### 6.3 索引

- 业务编号唯一性治理；成员 + 更新时间复合索引。
- 业务线 ID + 节点顺序复合索引。
- 负责人 + 节点状态复合索引。
- 节点 ID + 反馈时间复合索引。
- 业务线/节点 + 凭证时间复合索引。
- 邀请 token + 状态索引。

## 7. 权限与安全

### 7.1 权限矩阵

| 操作 | 业务线管理员 | 节点负责人 | 关联查看者 |
|---|---:|---:|---:|
| 查看业务线 | 是 | 是 | 是 |
| 编辑业务线/节点 | 是 | 否 | 否 |
| 邀请与绑定成员 | 是 | 否 | 否 |
| 反馈绑定节点 | 是 | 是 | 否 |
| 查看授权凭证 | 是 | 是 | 是 |
| 删除业务线 | 是 | 否 | 否 |
| 保存为模板 | 是 | 否 | 否 |

### 7.2 安全控制

- 云函数从可信微信上下文读取 OpenID，不接受客户端伪造用户 ID。
- 数据库关键集合设置为仅管理端写，防止绕过云函数。
- 所有读取按业务成员关系过滤，凭证临时地址按需获取。
- 文件扩展名、MIME、大小、数量进行白名单校验；文件名清洗，云路径使用随机标识。
- 高风险操作写入审计日志；删除、成员变更和权限变更保留前后摘要。
- 使用版本号或条件更新避免多人同时操作造成覆盖。
- 不在客户端代码存储 AppSecret、云密钥或订阅消息服务凭据。

## 8. 凭证方案

允许的 MVP 类型为 PDF、PNG、JPG/JPEG。客户端选择文件后直接上传云存储，再将 fileID、原文件名、类型和大小提交云函数绑定节点。预览图片使用图片预览能力；PDF 下载为临时文件后使用文档预览能力。

建议默认限制：单文件不超过 20 MB、单次不超过 9 个、节点累计上限可配置。生产环境需增加文件内容安全检测、病毒扫描或人工审查流程，并明确数据保留周期。

## 9. 通知方案与微信限制

节点激活时系统创建通知任务。只有在用户已对相应订阅消息模板授权且存在可用发送机会时，后端才发送微信订阅消息。授权弹窗必须由用户点击等主动行为触发；拒绝授权时，小程序仍需保留首页待办、节点红点和站内通知。

通知类型：节点到达、节点受阻、即将逾期、已逾期、业务完成。MVP 首先上线“节点到达”；其他类型在 P1 启用。

## 10. 检索与凭证查看

MVP 支持计划开始日期区间、业务名称关键字、业务编号关键字、业务状态组合筛选。小数据量阶段可由云函数进行受控过滤；当单用户业务量增长后，名称/编号改为标准化前缀字段或接入独立检索服务。

检索结果只返回用户有权查看的业务线。进入详情后按节点查看反馈历史与凭证，不直接暴露跨业务文件列表。

## 11. 非功能指标

- 可用性：关键页面请求失败应可重试并显示明确提示。
- 性能：首页首屏只加载统计和最近 5 条；列表分页；详情分批加载反馈与凭证。
- 一致性：创建业务线、完成节点和激活下一节点应使用事务或幂等补偿。
- 可审计性：关键写操作 100% 记录操作者、时间、对象和结果。
- 可维护性：统一云函数路由、统一错误码、集合常量和状态枚举。
- 兼容性：正式发布前覆盖主流 iOS/Android 微信版本与不同屏幕尺寸。

## 12. 隐私与合规

上线前必须在微信公众平台配置隐私保护指引，说明收集的用户标识、文件、业务信息及用途。凭证可能包含个人信息或商业敏感内容，应坚持最小收集、明确授权、按角色访问、到期删除和操作留痕。若业务涉及法律、金融、医疗等高敏领域，需要进一步开展专项合规评估。

## 13. 环境与发布

- 开发环境：开发者个人调试和自动化测试数据。
- 测试环境：体验版、固定测试人员、独立云环境。
- 生产环境：正式数据、严格权限、监控告警、备份和发布审批。

发布路径：本地开发 → 云函数部署 → 开发版验证 → 体验版 UAT → 隐私与类目检查 → 提审 → 灰度/正式发布。

## 14. 测试与验收

### 14.1 核心验收场景

1. 管理员创建含 3 个节点的业务线，首节点自动进入待处理。
2. 非成员不能读取业务详情；普通成员不能编辑或删除。
3. 负责人可反馈本人节点，不能反馈他人节点。
4. 强制凭证节点无文件时不能完成；上传 PDF/图片后可完成并预览。
5. 节点完成后下一节点自动激活，最后节点完成后业务线进度为 100%。
6. 按日期、名称、编号检索结果正确且不越权。
7. 业务线管理员可删除；其他角色删除请求被拒绝并留日志。
8. 模板创建的业务线节点顺序和规则与模板一致。

### 14.2 测试类型

- 云函数单元测试：权限、状态机、校验和错误码。
- 集成测试：数据库、云存储、消息队列、幂等与并发。
- 小程序真机测试：授权、文件选择、上传、PDF 打开、弱网和断网恢复。
- 安全测试：越权读取/写入、伪造 ID、恶意文件名、过大文件和重复提交。
- UAT：使用真实业务模板完成端到端演练。

## 16. 关键风险与对策

- 微信订阅消息授权不稳定：保留站内待办作为主路径，订阅消息作为增强提醒。
- “拉人”能力受平台限制：使用邀请链接/二维码与用户确认加入。
- 复杂权限导致越权：关键写操作全部云函数化，读取也按成员关系过滤。
- 凭证带来存储与合规压力：限制类型/大小、按角色访问、设置保留期与审计。
- 文档数据库跨集合一致性：关键流转使用事务/幂等键，失败任务进入补偿队列。
- 需求扩展为复杂工作流：MVP 保持顺序节点，条件/并行流转列入 P1。

## 17. 当前开发基线

仓库已建立微信小程序与 `businessApi` 云函数骨架，包含概览、业务列表、创建、详情、节点反馈、文件上传和模板入口。云函数已实现登录初始化、成员可见性、管理员删除、节点负责人反馈、强制凭证校验、下一节点激活和审计记录。

当前仍需配置真实 AppID、云开发环境、数据库集合/索引/权限和订阅消息模板后才能进行端到端联调。
