# 授权范围内的售后全流程内容检索设计

日期：2026-08-25

状态：产品规则与完整设计已确认，等待书面规格复核后生成实施计划。

## 1. 目标

现有售后列表只支持按售后名称和编号检索。本功能把检索范围扩展到售后全流程中当前有效的可见内容，同时维持严格的账号与售后访问边界。

用户输入一个或多个关键词后，可以匹配：

- 售后名称、编号和说明；
- 节点名称和节点编号；
- 节点动态字段的字段名称和当前有效值；
- 当前有效处理说明；
- 当前有效审核轮次中的审核意见；
- 当前有效凭证的文件名称。

检索只使用当前有效最新快照：

- 处理中节点使用当前处理轮最新已发布进度；
- 待审核节点使用当前活动审核轮的不可变提交快照和当前投票；
- 已完成节点使用最终通过审核轮的不可变内容；
- 已被驳回、替换或废弃的旧处理修订、旧审核轮和旧投票不参与命中。

## 2. 权限与可见范围

### 2.1 活动超级管理员

活动 `super_admin` 可以查看和检索全部非创建中、非已删除的售后，包括跨成员关系的全局结果和明细下钻。

该权限必须在候选读取后和返回结果前重新校验。账号被停用、删除或降权后，后续请求立即失去全局权限；不能继续使用旧页面、旧游标、旧索引结果或幂等结果读取全局内容。

### 2.2 普通活动账号

普通账号只可以检索其按现有售后关系原本有权查看的售后。授权继续使用当前账号制业务关系和兼容旧关系边界，不因全文索引建立新的查看权限。

### 2.3 防止权限旁路

- 无权售后不返回结果、命中摘要、命中数量、精确总数或“存在但无权”的错误。
- 损坏、缺失、版本过期或在请求期间被撤权的候选按无结果处理。
- 搜索游标与过滤条件绑定，不能把超级管理员游标交给普通账号继续翻页。
- 关键词、结果顺序、分页和错误信息均不能成为售后存在性旁路。
- 详细页面继续执行现有独立授权，搜索结果不替代详情授权。

## 3. 非目标

- 不检索历史已驳回轮次、被替换修订或旧凭证版本。
- 不检索云文件编号、永久云路径、哈希、请求键、预约信息、数据库文档编号、账号编号或系统运行元数据。
- 不提供跨账号的普通用户全局检索。
- 不提供语义搜索、拼音纠错、近义词、模糊编辑距离或相关性学习。
- 不返回精确全局命中总数。
- 不把未经权限复核的索引内容直接投影给客户端。
- 不修改历史售后、审核、凭证或保留期限的权威数据。

## 4. 用户输入与匹配规则

### 4.1 关键词

- 以一个或多个空白字符切分关键词。
- 最多 5 个关键词，规范化后总长度最多 100 个 Unicode 码点。
- 允许单字符关键词。
- 多关键词使用“同时满足”语义；关键词可以分别命中同一售后的不同节点或不同字段。
- 空关键词继续使用现有列表行为，不进入全文索引。

### 4.2 规范化

服务端统一执行：

1. Unicode NFKC 规范化；
2. 英文字母不区分大小写；
3. 连续空白折叠为一个空格；
4. 移除首尾空白；
5. 保留中文、数字、日期、选项名称和用户输入内容本身，不做不可逆分词替换。

布尔字段使用可见中文值“是”或“否”；单选和多选使用模板中的可见选项名称；日期和数值同时保留稳定格式化值。

### 4.3 精确命中

倒排索引只用于找到候选，最终必须对规范化后的可见文本做连续子串校验。哈希碰撞、短词公共片段或分块重叠不能直接构成命中。

单字符使用一元片段，双字符使用二元片段，三字符及以上使用三元片段作为候选锚点。所有关键词经过精确校验后才算命中。

## 5. 可检索内容模型

每个售后生成多个独立的安全检索条目。每个条目只保存一个可见内容来源，不生成包含整条售后所有文本的巨大文档。

条目来源包括：

- `line_name`：售后名称；
- `line_code`：售后编号；
- `line_description`：售后说明；
- `node_name`：节点名称；
- `node_code`：节点编号；
- `field_name`：动态字段名称；
- `field_value`：动态字段当前有效值；
- `processing_comment`：当前有效处理说明；
- `review_comment`：当前有效审核意见；
- `evidence_file_name`：当前有效凭证文件名称。

每个条目保存售后编号、可选节点编号、内容类型、受控标签、规范化文本片段和安全摘要。摘要不包含云路径、文件编号或内部账号信息。

长文本按最多 2048 个 Unicode 码点分段，相邻段保留 99 个码点重叠，确保最长 100 码点的查询不会因分段边界漏检。客户端摘要仍按更短的可见长度截断。

## 6. 数据结构

### 6.1 `business_search_documents`

新增仅云函数读写集合，保存版本化检索条目和令牌分块。

条目文档至少包含：

```js
{
  documentType: 'entry',
  businessLineId,
  nodeId: null | string,
  sourceKind,
  sourceVersion,
  generationId,
  entryId,
  label,
  normalizedText,
  safeExcerpt,
  segmentIndex,
  createdAt
}
```

令牌文档至少包含：

```js
{
  documentType: 'tokens',
  businessLineId,
  nodeId: null | string,
  sourceVersion,
  generationId,
  entryId,
  tokenHashes,
  tokenChunkIndex
}
```

`tokenHashes` 使用独立密钥计算 HMAC 后截断为稳定、不可逆、固定长度的标识。每个数组分块在测试中按真实 BSON 结构核算并保持在保守 768 字节索引预算内；不得仅按元素数量猜测安全上限。

### 6.2 `business_search_requests`

新增仅云函数读写集合，保存短期一次性内部索引票据。原始随机票据只在内存和云函数调用参数中出现，数据库只保存不可逆摘要、目标售后、目标版本、状态和过期时间。

票据必须：

- 使用至少 192 位安全随机值；
- 在事务中从 `pending` 原子转为 `consumed`；
- 拒绝过期、重放、跨售后、跨版本或损坏票据；
- 不接受客户端身份直接调用；
- 不保存原始业务请求键。

### 6.3 权威来源版本

售后和节点增加：

```js
searchSourceVersion
searchGeneratedVersion
searchIndexStatus
searchGeneratedAt
```

规则如下：

- `searchSourceVersion` 和 `searchGeneratedVersion` 必须是非负安全整数；
- 可检索内容发生变化时，在原权威业务事务中递增来源版本并标记 `pending`；
- 纯时限补算、提醒游标、已读回执和与检索内容无关的元数据变化不递增版本；
- 只有完整生成且最终版本复核成功后才写 `generated`；
- 任意非法、缺失或溢出值失败关闭。

审核投票虽然写入独立审核轮次和投票文档，事务仍需同步推进所属节点的检索来源版本。所有新增固定文档操作必须纳入 100 次事务硬上限测试。

## 7. 组件边界

### 7.1 `business-search-domain`

负责：

- 关键词解析和 Unicode 规范化；
- 可见字段值格式化；
- 内容类型白名单；
- 文本分段和重叠；
- HMAC 令牌生成；
- 安全摘要裁剪；
- 版本、游标和数量边界校验。

该模块为纯函数，不访问数据库、网络或当前账号。

### 7.2 `cloud-business-search-repository`

负责：

- 严格读取当前权威售后、节点、最新反馈、当前或最终审核轮次、当前投票和凭证文件名；
- 写入独立新代索引；
- 事务消费内部票据；
- 事务复核来源版本并切换生成版本；
- 有界令牌候选读取、精确文本复核和旧代清理；
- 历史回填游标和恢复候选扫描。

仓储不返回未经授权的客户端结果。

### 7.3 `business-search-service`

负责：

- 编排同步索引生成；
- 编排关键词检索；
- 组合命中条目并限制摘要数量；
- 处理可恢复索引状态和稳定错误投影。

### 7.4 `businessSearch` 云函数

新增独立云函数：

- 人工同步路径只接受 `businessApi` 签发的一次性内部票据；
- 恢复和历史回填路径只接受服务端 `process.env.TRIGGER_SRC === 'timer'` 且拒绝非空 `OPENID`；
- 事件中的 `Type`、时间、模式或目标编号均不能授予权限；
- 默认部署必须保持 `triggers: []`。

### 7.5 `businessApi`

现有售后写入在权威事务内标记待索引；事务提交后签发一次性票据并调用 `businessSearch`。现有列表接口扩展为：

- 无关键词：保持现有售后列表行为，并允许活动超级管理员查看全部非创建中、非已删除售后；
- 有关键词：调用检索服务，并按同样权限规则返回命中摘要；
- 普通账号继续仅返回当前有权售后；
- 返回前重新读取当前账号和每条候选售后的关系。

## 8. 当前有效快照选择

### 8.1 处理中节点

- 只读取当前 `processingRoundNumber` 下最新 `publishState: published` 的反馈；
- 字段值和处理说明以最新修订为准；
- 凭证文件名取该处理轮仍有效且归属严格一致的凭证全集；
- 前一处理轮和被替换的旧修订不进入索引。

### 8.2 待审核节点

- 读取 `activeReviewRoundId` 指向的当前审核轮；
- 使用轮次固化的字段值、处理说明和凭证编号；
- 审核意见只读取与该轮次严格关联的当前投票；
- 损坏票据、重复票或归属不一致时该来源失败关闭。

### 8.3 已完成节点

- 读取节点最终通过的审核轮；
- 要求轮次 `status` 与 `finalDecision` 均为 `approved`，且业务、节点、处理轮次和审核轮次关系一致；
- 使用最终轮次的字段、处理说明、凭证和最终投票意见；
- 旧驳回轮次保持历史可读，但不参与当前检索。

### 8.4 等待节点和终态售后

- 尚未开始的节点只索引节点名称和节点编号；
- `completed`、`closed`、`cancelled` 等仍可查看的终态售后可以检索；
- `creating` 和 `deleted` 售后不进入结果。

## 9. 写入一致性与重试

### 9.1 同步可见性

所有改变当前可检索内容的成功写入必须完成对应索引生成后，才向客户端返回普通成功结果。业务权威事务一旦提交，索引失败不能回滚已经发生的售后变化。

此时接口返回稳定的可恢复状态，客户端显示：

> 内容已保存，检索索引正在生成，请稍后重试

同一请求键重试时：

- 不重复创建反馈、审核轮次、投票、审计、通知或业务变化；
- 只检查目标来源版本并恢复索引生成；
- 生成已完成时返回原业务结果；
- 账号或售后关系已变化时仍先重新授权。

### 9.2 新代发布

索引工作器先用新 `generationId` 写入完整条目和令牌，再在一个固定文档事务中重新读取目标售后和节点：

1. 当前来源版本必须等于工作版本；
2. 当前账号或可信工作器来源必须合法；
3. 新代文档数量和摘要必须完整；
4. 将 `searchGeneratedVersion` 切换到来源版本；
5. 将状态写为 `generated` 并记录生成时间。

旧代在切换后立即失去可见性，随后由有界清理批次删除。查询永远不混用两个代际。

### 9.3 并发

如果版本 N 生成期间权威内容推进到 N+1，版本 N 可以保留为未发布废代，但不能切换为当前索引。N+1 的重试或恢复工作器继续生成最新代。任何单边版本提升、版本回退或安全整数溢出均失败关闭。

## 10. 历史回填与恢复

历史回填使用 `system_settings` 中的版本化持久游标：

- 单次原始扫描最多 40 条售后或节点；
- 使用权威排序字段加 `_id` 的严格 keyset 后继，不使用 `skip`；
- 即使整页候选均失效，也推进原始扫描游标；
- 页尾安全回绕；
- 游标字段缺失、类型错误、访问器、继承值、版本损坏或修订溢出时失败关闭；
- 旧数据只通过明确兼容适配器读取，不猜测损坏结构；
- 每条历史来源独立生成，单条失败不阻断其他合法来源；
- 恢复工作器同时处理 `pending`、过期生成租约和未发布废代。

历史回填期间，未完成索引的售后不会被旧代或部分索引误命中。现有名称和编号检索可继续走原安全路径，直到该售后当前代完整生成。

## 11. 查询、分页和结果

### 11.1 候选与授权

查询仓储使用令牌倒排流生成有界候选，按 `businessLineId` 交集实现多关键词“同时满足”。每次请求的原始候选和固定文档授权次数均设上限，不做全库扫描。

对每个候选依次执行：

1. 读取当前活动账号；
2. 判定活动超级管理员全局权限，或普通账号现有售后关系；
3. 读取当前售后状态和当前生成版本；
4. 只接受与当前生成代一致的条目；
5. 对每个关键词做规范化连续子串复核；
6. 返回前再次复核当前账号和售后关系。

### 11.2 游标

关键词查询使用服务端生成的安全游标，绑定：

- 规范化关键词摘要；
- 售后状态和其他筛选条件摘要；
- 当前账号编号和权限级别；
- 上一候选排序位置；
- 游标版本和过期时间。

客户端不能修改或跨账号复用。接口返回 `hasMore`，不返回需要全库扫描的精确总数。

### 11.3 展示

每条售后最多展示 3 个命中摘要，每个摘要包含：

- 节点名称；
- 内容类型或动态字段名称；
- 截断后的安全命中文本。

用户可以展开查看更多当前命中，但展开结果仍受同一授权、版本和数量边界限制。结果中不展示内部编号、云路径或不可见历史。

## 12. 错误处理

稳定错误和用户提示如下：

- 关键词为空、超长、超过 5 个或格式非法：提示调整检索内容；
- 索引正在生成：提示“内容已保存，检索索引正在生成，请稍后重试”；
- 索引暂时不可用：提示“检索服务暂时不可用，请稍后重试”；
- 无权、缺失、撤权、版本过期或损坏候选：作为无结果，不暴露具体原因；
- 未知数据库、索引或云函数异常：统一安全错误，不返回集合名、索引名、请求票据、云路径或堆栈。

日志只记录稳定错误码、阶段和安全计数，不记录关键词原文、字段内容、凭证名称或用户可识别数据。

## 13. 密钥与部署安全

新增独立环境变量：

```text
BUSINESS_SEARCH_HMAC_SECRET
```

该密钥由 `businessApi` 和 `businessSearch` 共同使用，只用于令牌与游标完整性，不复用公开分享密钥、恢复密钥或密码材料。不得写入 Git、项目记忆、日志或客户端。

部署顺序：

1. 备份现有售后、节点、反馈、审核轮次、投票、凭证及系统设置；
2. 创建 `business_search_documents` 和 `business_search_requests`，设置仅云函数读写；
3. 创建手册列明并由真实查询形状验证的组合索引；
4. 在两个云函数中安全配置同一检索密钥；
5. 部署 `businessSearch`，保持 `triggers: []`；
6. 部署 `businessApi` 和小程序；
7. 使用一次性可信 Timer 验证历史回填和恢复；
8. 验收完成后恢复空触发器；
9. 另行批准固定恢复周期，不自动启用正式 Timer。

## 14. 自动化测试

实施必须先补失败测试，再完成最小实现。至少覆盖：

### 14.1 匹配规则

- 单字符、双字符、长关键词；
- Unicode NFKC、英文大小写和空白折叠；
- 最多 5 词、总长 100 和非法输入边界；
- 多关键词分别命中不同节点和不同字段；
- 中文、数字、日期、布尔、单选和多选字段；
- 节点名称、编号、处理说明、审核意见和凭证文件名；
- 分块边界和 100 码点最长查询；
- HMAC 锚点碰撞后精确校验拒绝假命中。

### 14.2 当前快照

- 处理中只命中最新保存内容；
- 待审核命中当前轮提交快照和当前投票；
- 已完成只命中最终通过内容；
- 旧驳回轮、旧修订和已替换凭证不命中；
- 返工后旧轮内容不污染新处理轮；
- 等待节点只命中节点元数据。

### 14.3 权限

- 活动超级管理员可检索全部合法售后；
- 超级管理员停用或降权后立即失去全局结果；
- 普通成员、管理员和兼容旧关系仅命中原可见售后；
- 无关普通账号不获得结果、摘要、总数或存在性错误；
- 查询中途撤成员关系、停用账号、删除售后时返回前隐藏；
- 游标跨账号、跨权限或篡改时失败关闭；
- 详情下钻继续执行独立授权。

### 14.4 一致性与恢复

- 权威写成功、索引失败后业务不回滚；
- 同请求重试只恢复索引，不重复业务副作用；
- 同版本重复生成幂等；
- N 和 N+1 并发时只有最新完整代可发布；
- 部分条目、部分令牌、缺失摘要或版本单边变化不发布；
- 第 41 条历史候选有限可达；
- 全失效页推进、尾页回绕、崩溃重试和并发游标领取；
- 损坏游标、损坏旧数据和版本溢出失败关闭；
- 废代有界清理不影响当前查询。

### 14.5 预算与回归

- 所有新增事务路径按真实文档操作计数不超过 100；
- 令牌数组按真实账号/文本长度验证保守 768 字节索引预算；
- 大文本和多节点不产生单文档无限增长；
- 现有售后列表无关键词行为保持兼容；
- 普通售后创建、进度保存、提交审核、投票、返工、凭证、公开分享、提醒、日历、保留和运营统计全量回归通过；
- 小程序 WXML、输入白名单、错误脱敏和异步账号切换回归通过。

## 15. 人工验收

在真实 CloudBase 隔离数据中至少完成：

1. 创建包含多个节点和全部字段类型的隔离售后；
2. 分别保存、提交、驳回、返工并最终通过，证明只有当前快照命中；
3. 使用分散在不同节点的多个关键词检索同一售后；
4. 普通参与账号只能看到有权售后；
5. 无关普通账号看不到隔离售后及任何存在性信号；
6. 活动超级管理员可以全局检索并下钻；
7. 停用或降权超级管理员后立即失去全局结果；
8. 凭证文件名可命中，但页面与日志不泄漏云路径和文件编号；
9. 模拟索引生成中断，再用同请求恢复且不重复业务副作用；
10. 使用一次性 Timer 回填历史，确认游标、代际、索引数量和空触发器；
11. 重新编译小程序，核对三条摘要、展开、空状态、翻页和中文安全提示。

## 16. 回滚

回滚旧版 `businessApi` 和小程序后，新增集合及版本字段会被旧代码忽略，不影响权威售后流程。回滚时：

- `businessSearch` 恢复 `triggers: []`；
- 停止历史回填和恢复工作器；
- 保留索引集合用于审计和后续恢复，不立即删除；
- 不删除或回写售后、节点、反馈、审核、投票或凭证权威数据；
- 若重新启用新版，先核对密钥、集合权限和索引，再从当前权威内容重建新代。

## 17. 实施边界

本规格是单一可实施子项目，包含检索索引、同步生成、历史回填、权限复核和列表展示。它不包含语义搜索、外部搜索服务、搜索分析看板或历史全文审计检索。

下一步在本规格经书面复核确认后，生成详细实施计划；实现必须按测试驱动方式分任务落地，不得跳过真实 CloudBase 部署与多账号权限验收。
