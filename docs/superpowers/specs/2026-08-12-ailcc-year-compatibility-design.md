# AILCC 全年接口年份兼容设计

## 背景

目标环境人工同步工作日历时，`businessApi` 与 `calendarSync` 均可正常调用，但 2026、2027 两个年份均返回 `SYNC_FAILED`。AILCC 当前接口文档明确将 `year` 返回为四位数字字符串，例如 `"2026"`；现有解析器只接受数字 `2026`，因此会拒绝结构合法的响应。

## 决策

- `normalizePayload` 同时接受与请求年份严格相等的安全整数，或内容完全等于四位请求年份的字符串。
- 不接受空白、前导零、小数、指数、带符号、其他年份或其他类型。
- 日期数量、全年自然日覆盖、日期唯一性和 `is_holiday` 严格 0/1 校验保持不变。
- 规范化后的内部年份继续使用数字，既有持久化结构不变。
- 第三方接口不可用或下一年度数据尚未发布时继续按年份安全返回 `SYNC_FAILED`，不猜测日历。

## 验证

先增加字符串年份失败回归，再做最小实现；运行 `calendarSync` 全量、项目核心全量、WXML、差异与项目记忆校验。完成后只重新部署 `calendarSync` 并重新执行受保护的人工同步。
