# 节点大凭证可靠上传与交互性能优化设计

日期：2026-08-28  
状态：方案已获产品批准，待书面复核后实施

## 1. 背景与已确认问题

节点凭证目前使用 `wx.cloud.uploadFile` 单次直传，登记时由 `businessApi` 下载完整对象校验。客户端和服务端仍执行旧的图片 5 MB、PDF/视频 20 MB、单轮合计 20 MB 限制。真实设备已出现以下问题：

- Mac 微信客户端的“选择图片或视频”使用 `wx.chooseMessageFile({ type: 'file' })`，该模式排除图片和视频，导致聊天文件列表中的媒体灰显不可选；
- 15.2 MB MP4 在旧直传链路中失败，页面只显示通用错误，无法区分选择、网络、存储或登记失败；
- iPhone 和开发者工具出现“提交审核失败”但后台实际提交成功，用户误以为失败并担心已填内容丢失；
- 节点凭证新的产品规则为：同一处理轮当前有效凭证总和不超过 120 MB，不额外设置业务层单文件上限，也不设置业务层文件数量上限；
- Apple 与部分 Android/Huawei 设备可能产生 HEIC/HEIF、MOV、H.265/HEVC 等媒体，旧扩展名白名单不足；
- 概览页当前一次刷新发出三次云函数调用，节点处理页串行读取售后详情和节点历史，未保存草稿的提交审核至少发出“保存进度”和“提交审核”两次业务调用；
- 权威写入提交后，检索同步失败会返回 `BUSINESS_SEARCH_PENDING`，客户端因此显示失败，即使节点状态已经改变。

腾讯云官方建议超过 100 MB 的对象使用 COS 小程序 SDK 高级上传，由 SDK 自动选择简单上传或分块上传，并使用服务端签发的临时密钥和路径级最小权限。CloudBase 官方同时建议通过复用模块级初始化、裁剪依赖、适当提高内存以及在支持的函数类型上启用请求多并发降低冷启动。本设计采用其中与当前事件云函数和安全边界兼容的部分。

## 2. 目标

1. 同一处理轮允许任意数量凭证，只要服务端权威合计不超过 120 MiB。
2. 单个文件只受上述合计规则推导出的 120 MiB 物理上界，不再额外显示或执行 5/20 MB 产品限制。
3. iOS、Android、Mac 和 Windows 均可选择并上传受支持的常见图片、视频和 PDF。
4. 大文件使用可恢复的分块上传；网络中断只重试未完成分块，不要求重新填写字段。
5. 服务端继续校验当前账号、售后、节点、处理权限、节点版本、真实对象大小和文件签名；永久云密钥不得进入小程序。
6. 提交审核的权威结果与页面提示一致；不再因派生检索暂时失败把成功写入显示为失败。
7. 减少常用页面云函数往返数，保留已有内容时后台刷新，避免每次返回页面都白屏等待。
8. 不削弱凭证保留、公开分享、审核冻结、版本冲突和分块预约协议。

## 3. 非目标

- 不开放任意可执行文件、压缩包、Office 文档或未知二进制格式。
- 不删除服务端真实格式校验，不以客户端扩展名或 MIME 声明作为唯一依据。
- 不承诺所有设备原生预览 HEIC/HEIF 或 H.265/HEVC；不支持原生预览时仍必须能安全下载原件。
- 不在本轮把全部云函数迁移到云托管或 HTTP 云函数。
- 不以关闭检索、权限复核、版本控制或内容完整性校验换取表面速度。

## 4. 文件选择与格式规则

### 4.1 选择器

- iOS/Android 图片和视频继续使用 `wx.chooseMedia`，允许相册和相机。
- Mac/Windows 微信客户端使用 `wx.chooseMessageFile({ type: 'all' })`。桌面端仍会由微信展示聊天/文件来源，这是平台行为；改为 `all` 后媒体不再因 `type: 'file'` 被排除。
- PDF 入口继续使用消息文件选择器；两个入口选出的结果最终进入同一规范化与校验流程。
- 每次选择数量可受微信接口限制，但用户可重复选择；应用不设置总文件数上限。

### 4.2 系统支持格式

- 图片：`jpg`、`jpeg`、`png`、`webp`、`heic`、`heif`；
- 视频：`mp4`、`mov`、`m4v`，容器内允许 H.264 和 H.265/HEVC；
- 文档：`pdf`。

模板的非空格式白名单仍严格生效；“非必传 + 空白名单”继续表示允许全部系统支持格式。模板管理页同步增加新增扩展名选项。文件扩展名、容器签名或头部品牌不一致时失败关闭。

### 4.3 跨设备预览

- JPG/JPEG/PNG/WebP 使用现有图片预览。
- HEIC/HEIF 保留原件。若目标 COS 已开通数据万象且原图满足其处理限制，则生成或按需获取 JPG 兼容缩略图；否则页面显示安全文件卡和“下载原件”，不把预览失败误报为上传失败。
- MP4/MOV/M4V 先尝试原生播放器；设备不支持该编码时显示下载原件，不在上传阶段强制转码。
- PDF 继续使用下载后的文档预览。

## 5. 上传架构

### 5.1 生命周期

每个本地文件依次经历：

`pending → authorizing → uploading → uploaded → verifying → available`

失败状态保留已完成分块、上传会话和本地表单。用户可重试当前文件或删除它，不影响其他已登记凭证。

### 5.2 受保护上传会话

新增 `beginEvidenceUpload`：

1. `businessApi` 重新读取活动账号、售后、当前节点、处理角色、节点版本和模板凭证策略；
2. 校验规范化文件名、扩展名、声明大小和本轮已有可用凭证合计；
3. 在 `evidences` 创建不可见的 `storageStatus: 'uploading'` 预约，写入随机上传会话摘要、精确对象键、声明大小、节点版本、15 分钟会话到期时间和 24 小时孤立到期时间；
4. 返回只允许该一个对象键执行上传和分块操作的短期 COS 凭证、桶、地域、对象键和会话令牌；
5. 永久 `SecretId`、`SecretKey`、CloudBase 管理凭证和其他对象路径不得返回客户端。

对象键使用服务端生成的凭证编号和受控扩展名，不直接拼接用户原始文件名。

慢速网络可能让 90–120 MiB 分块上传跨越单份凭据的 15 分钟期限。客户端在到期前两分钟或收到明确凭据过期错误时调用 `refreshEvidenceUploadAuthorization`；服务端以原预约令牌重新执行当前账号、售后、节点、版本、轮次、角色和格式策略授权，只更新原预约的会话到期时间并为同一对象键签发新凭据。客户端并发刷新单飞、单文件最多刷新八次，授权刷新不消耗普通传输重试预算，重试后的进度不得回退；任何预约、对象键或作用域不一致都失败关闭。

### 5.3 COS 高级上传

小程序使用固定版本的腾讯云 COS 小程序 SDK高级 `uploadFile`：

- SDK根据体积自动选择简单或分块上传；
- 同时上传最多 3 个文件，每个文件分块并发使用 SDK 的保守默认值；
- 显示每个文件和本轮总进度；
- 网络错误执行有界指数退避，用户主动取消、权限变化或节点版本变化立即停止；
- 只向受信任的 COS 域名发送临时凭证；
- `requiredPrivateInfos` 增加 `chooseMedia`，并在发布前复核隐私声明。

### 5.4 服务端完成登记

新增 `finalizeEvidenceUpload`：

1. 再次复核活动账号、售后、节点、处理权限、节点版本、上传会话归属和未消费状态；
2. 通过 COS 服务端接口读取对象元数据和有界头部字节，不把最多 120 MiB 的完整文件加载到 256 MB 云函数内存；
3. 以服务端 `Content-Length` 为真实大小，以文件签名和 ISO-BMFF `ftyp` 品牌区分图片、视频和 PDF；
4. 记录 COS 提供的 CRC64/ETag 等服务端完整性值及算法；旧记录的 `sha256` 保持兼容，新记录不伪造全文件 SHA-256；
5. CAS 更新为 `storageStatus: 'available'` 并清除上传会话凭证，只返回安全凭证编号、名称、类别和大小。

完成登记按上传会话幂等；响应丢失后重试返回同一凭证，不创建重复记录。上传后未完成登记的预约继续由 `evidenceRetention` 按孤立规则有界清理对象和元数据。

## 6. 120 MiB 权威合计

- 客户端用本地大小提前提示，但它只是体验优化。
- `beginEvidenceUpload` 只允许声明大小为安全非负整数且不超过 120 MiB；该上界是总量规则的数学结果，不作为独立产品限制展示。
- `finalizeEvidenceUpload` 使用服务端真实对象大小重新校验。
- 保存进度和提交审核的最终事务按当前处理轮全部有效凭证的服务端大小求和，超过 `120 * 1024 * 1024` 返回 `FEEDBACK_TOTAL_TOO_LARGE`。
- 并发上传可能分别通过预约，但最终合计必须失败关闭；客户端保留文件并明确提示需要删除部分凭证后重试。
- 旧 20 MiB 数据无需迁移，历史记录继续有效。

## 7. 提交一致性与失败恢复

### 7.1 单一提交入口

新增 `saveAndSubmitNodeForReview`，只用于审核模式且本地内容发生变化的节点：

- 一个客户端云函数调用内先按现有分块预约协议保存字段、说明和凭证，再按得到的新节点版本创建审核轮次；
- 两阶段各自保留现有请求键、摘要、版本和幂等恢复规则；任一响应丢失后，相同请求重试只能恢复结果，不能重复反馈、审核轮次、通知或审计记录；
- 已有干净服务端草稿仍直接走 `submitNodeForReview`，不重复保存。

### 7.2 权威成功不被派生索引覆盖

- 反馈、审核和售后权威事务提交后，检索同步失败不得把响应改为业务失败；返回成功数据并附 `searchIndexStatus: 'pending'`。
- 同源版本继续保持待生成状态，由现有 `businessSearch` 恢复入口补算；客户端不向用户展示派生索引错误。
- 只有权威事务本身失败才解锁按钮并保留全部字段和已上传凭证。
- 对超时、断网等结果不确定错误，客户端用同一请求键查询节点工作区：若已进入 `pending_review` 或存在对应审核轮次，显示“已提交审核”；否则恢复可编辑状态并允许原请求重试。

## 8. 响应性能优化

### 8.1 可测量基线

`callBusinessApi` 增加不含账号、正文、文件名或关键词的安全计时：只记录动作枚举、成功/失败分类、客户端耗时和是否为开发环境。上传单独记录授权、分块上传、完成登记三个阶段耗时。生产日志不得记录用户内容。

### 8.2 减少往返

- 概览：新增单一 `getDashboardWorkspace`，服务端并行获取统计、待审核计数和未读通知计数，一次返回首屏安全投影；替代客户端三次并发云函数调用。
- 节点处理页：新增 `getNodeWorkspace`，一次返回当前节点安全详情、字段定义、最新草稿、权限和历史；服务端在完成售后授权后并行读取可并行的数据，替代客户端两个串行调用。
- 提交：脏草稿使用 `saveAndSubmitNodeForReview`，把两个客户端往返合为一个；凭证上传仍在提交前独立完成并可恢复。
- 成功保存进度后优先用返回的新版本和新增历史安全投影局部更新页面；仅在返回数据不完整、版本冲突或账号变化时整页重载。

### 8.3 页面缓存与刷新

- 概览和售后详情保留当前已渲染内容，返回页面时静默刷新，不重新切换到整页加载态。
- 内存缓存必须按当前内部账号编号隔离，登录、登出、解绑、停用或账号切换立即清空；不持久化正文到本地存储。
- 节点编辑页的本地脏草稿继续优先于后台刷新，已有的账号、页面序列和版本保护保持不变。

### 8.4 云函数配置

- `wx-server-sdk`、数据库和服务对象继续模块级初始化；请求相关状态不得放入模块级可变变量。
- `businessApi` 生产内存从 256 MB 做 512 MB A/B 验收：比较冷启动、持续时间和费用后再决定是否长期保留。
- 事件云函数不假定存在“请求多并发”开关；只有控制台对当前函数类型明确提供且并发安全测试通过后才启用。
- 不把 `businessApi` 拆分或迁移云托管作为本轮前置条件。

### 8.5 验收目标

在同一网络、同一账号和同一测试数据下比较变更前后：

- 概览首屏：客户端云函数调用从 3 次降为 1 次；
- 节点处理页首次完整数据：从 2 次串行调用降为 1 次；
- 无新凭证的脏草稿提交审核：从 2 次客户端业务调用降为 1 次；
- 热实例且不含上传时，概览/节点工作区目标 P50 不高于 1.5 秒、提交目标 P50 不高于 3 秒；冷启动和弱网单独记录，不伪装成热实例指标；
- 返回已有页面时立即保留旧内容并显示轻量刷新状态，不出现空白页。

## 9. 测试策略

所有修改先写失败测试，再做最小实现。自动化至少覆盖：

1. 120 MiB 边界、总量超限、并发预约超限和不限文件数量；
2. JPG/JPEG/PNG/WebP/HEIC/HEIF、MP4/MOV/M4V、H.264/H.265 与 PDF 的签名/品牌匹配；伪造扩展名、未知二进制和危险文件拒绝；
3. 桌面 `type: 'all'`、移动 `chooseMedia`、重复选择和不同模板白名单；
4. 临时凭证只能访问单一对象键，过期、串账号、串售后、串节点、旧版本和重放失败；
5. 分块重试、完成登记幂等、上传未登记的孤立清理；
6. 脏草稿单调用提交、响应丢失恢复、真实失败解锁且字段不丢、索引失败仍返回权威成功；
7. 概览和节点工作区请求数、并行仓储读取、账号缓存隔离、脏草稿不被刷新覆盖；
8. 公开分享、审核详情、历史下载和 60 天保留对新完整性字段的兼容；
9. 完整 `businessApi`、`businessSearch`、`evidenceRetention`、小程序、WXML、语法、差异和项目记忆门禁。

## 10. 部署与回滚

部署顺序：

1. 备份 `evidences`、`node_feedback`、`business_nodes` 和相关环境变量；
2. 配置 COS 桶/地域、服务端长期凭证或等价角色凭证、路径级 STS 权限以及小程序合法域名；长期凭证只存在服务端；
3. 先部署兼容旧客户端的 `businessApi` 与 `evidenceRetention`；
4. 部署含 COS SDK 的小程序开发版，使用无敏感隔离文件验证简单上传、分块上传、重试、预览、提交和清理；
5. A/B 验证 256 MB 与 512 MB 后再调整正式内存；
6. 完成 iPhone、Huawei/Android、Mac 和 Windows 真实微信验收，再上传审核版本。

回滚时先回退小程序到旧上传入口，再回退云函数。已经完成的 `available` 凭证、反馈、审核轮次和审计记录不得删除；`uploading` 预约由保留任务按孤立规则清理。旧客户端不认识新增格式时应只显示安全文件卡，不得破坏历史读取。

## 11. 人工验收清单

- Mac/Windows 可从微信提供的来源选择图片、视频和 PDF，媒体不再灰显；
- iPhone HEIC、Huawei/Android 图片、H.264 和 H.265 视频均能上传或得到明确设备兼容提示；
- 单个约 110 MiB 测试视频和多文件合计恰好 120 MiB 成功，超过 120 MiB 明确失败；
- 90–120 MiB 文件在限速到超过 15 分钟时刷新同一预约、同一对象键后续传成功，期间没有重复凭证且进度单调；
- 上传中断后重试不重新填写字段，不重复生成凭证；
- 点击提交审核只出现一个最终结果，后台成功时页面必然显示成功；
- 概览、售后详情和节点处理页调用次数达到本设计目标，账号切换不显示前一账号缓存；
- 新凭证在历史、审核、公开分享、下载和保留清理中均按原权限工作。
