# B1：完整导出读取去重设计

日期：2026-09-24（Asia/Shanghai）。状态：用户已确认规格及实施计划并批准实施；本地改动、完整自动回归和一次最终独立复核已完成，未发布。本文承接容量与可靠性A基线，不代表月度容量问题已解决。实际结果见 `docs/deployment/export-read-deduplication-acceptance.md`。

## 1. 目标和保护范围

在同样的授权、数据和报告内容下，减少完整CSV导出每页的重复数据库读取。保留云开发，不引入新集合、索引、后台任务、持久报告或通用缓存框架。

规划输入仍为约50名员工、30条售后/天、每条平均100MB附件；不是50并发承诺，也不改变120MiB每处理轮附件限制。安卓、鸿蒙、iOS、macOS、Windows现有前端功能均受保护：CSV列、内容、顺序、分页和“生成文件→发送文件”操作不变。任何其他实际功能、权限或错误语义影响，须先获用户批准，不能以性能收益抵消。

## 2. 当前证据与方案选择

`cloud-operations-field-repository.js` 的完整导出每页都会发现候选来源、读取并通过事务核验最终结果；构造或复用报告后，再读取节点、反馈和审核轮次，然后进入第二次事务重新读取相同文档核验。事务外的第二次预读不是最终权威数据。

`cloud-operations-repository.js` 的 `reportBaseSnapshot` 复用 `dataset`，读取售后、节点、显示名和待审核轮次；报告基础行及来源清单不使用其中的待审核列表。运营仪表数据的待审核计数仍使用该列表，不能整体删除这段查询。

A基线的150个无审核完成节点，报告v1/v2首个及最后一个完整分页各1789次逻辑读取；2万读预算仅完成11页、550行。这是本地合成样本的逻辑调用量，不是线上耗时、计费量或完整报告成功证明。月度4500节点仍受现有2000候选节点限制。

选用**请求内固定来源标识复用，保留首尾权威核验**。不采用“删除首次事务、仅在返回前检查”：那会改变首次来源判定时点，扩大影响范围。持久报告和异步导出另行设计，不在B1中预建。

## 3. 读取职责和数据流

### 3.1 首次收集：原行为不变，记录内部标识

保留当前账号检查、游标验证、候选发现、日期与人员筛选、完整来源构造、首次事务核验和售后权限复核。仅在完整导出路径中，为成功通过首次核验的最终节点保存请求内来源引用：售后ID、节点ID、最终反馈ID、审核轮次ID（无审核时为空）。

引用必须来自此次已核验的来源，不能从客户端或旧报告缓存接收。以节点ID为键，与公开的结果、分析记录和来源清单分开存放；不加入 `records`、`analysisManifest`、报告摘要、游标、缓存条目、CSV或日志。引用只提供下一次读取的地址，不提供数据新鲜度或授权证明。

生命周期限于单次 `exportReportRows` 调用。每个续页仍重新发现候选并收集来源，不能跨页、跨账号或跨请求复用引用。非导出统计、筛选、关联分析和派生快照刷新不建立这个引用表。

### 3.2 报告基础数据：明确排除不使用的待审核列表

为内部 `dataset` 增加职责明确、默认保持旧行为的读取选项，仅完整报告的 `collectReportBase` / `validateReportBase` 使用“不读取待审核列表”模式。不要把此语义隐含绑定到现有的批量节点读取开关。

完整报告仍重新查询匹配创建日期的售后及其节点、读取必要的历史显示名，并构造或比较完整基础来源清单；不能只核对旧缓存里的ID，否则会漏掉新加入的记录。原 `getDashboard` 和旧 `exportRows` 保持原查询及计数行为。

**本规格已明确披露的影响：**完整报告将不再受无关待审核列表查询的延迟或故障阻断。这不是吞掉异常，而是不发出这项无关请求。与报告最终结果相关的审核轮次、审核票或任何仍需读取的来源失败，继续拒绝导出；待审核页面不受此调整影响。

### 3.3 返回前核验：省预读，不省权威读取

对每个将被导出的最终结果，使用本请求保存的固定来源标识直接进入现有核验职责，省去事务外重复读取节点、最终反馈和审核轮次的步骤。

有审核的节点仍需在最终事务之前，按该审核轮次**重新扫描审核票集合**，沿用50条上限，随后在事务中读取本次发现的审核票文档。不能仅复用首轮审核票ID：现有审核轮次文档没有可独立证明完整票集合的权威清单，只复用旧ID可能漏掉新增加或替换的票。

最终事务仍重新读取当前账号、售后、节点、固定最终反馈、固定审核轮次及新发现的审核票，以现有域逻辑重建最终结果并比较 `sourceDigest`。最新反馈或审核轮次标识发生变化时，即使可见字段相同也必须拒绝旧报告。引用缺失或不一致不能跳过核验或降级放行。

保留最后的售后身份与账号权限复核，以及现有并发上限4和事务操作预算。仅全部检查通过后才缓存并返回当页报告；不缓存权限判定或域核验结果。错误继续沿用现有映射，例如尾部来源失效转为 `REPORT_CHANGED`，账号撤权为 `FORBIDDEN`。

此设计保留现有扫描及逐节点事务边界，不新增“整个报告在一个数据库快照中完成”的承诺；不能宣称消除了扫描后、各事务之间的所有并发窗口。

## 4. 不变的外部契约与未解决限制

- 保留v1（包括未显式指定版本）与v2报告的全部基础列、字段明细、选项频次、关联分析、行顺序和日期口径；零值、false、空值、隐藏字段、公式保护及换行处理不变。
- 报告仍仅允许当前有效超级管理员；每页重新发现来源、检查权限。新增/移除候选、未匹配分析候选变化等，继续由现有清单语义判定，不改成只校验已导出行。
- 游标加密格式、账号/查询/报告摘要绑定、偏移和20分钟有效期不变。有效的旧实现游标在相同数据下仍可续页；不要求随机加密字符串逐字一致。
- 沿用现有最多3份、合计12MiB的进程报告缓存；冷实例续页与缓存淘汰后续页仍可重建相同内容，不能要求前一页必须命中同一实例。
- 保留2000候选节点、5000候选售后、10000扫描节点、50000报告行和12MiB报告预算。完整性不足、来源变化、过期和超限继续明确返回，不能下载残缺报告。
- 暖缓存原本已经减少报告重复构造；B1不把这项已有能力算作新增收益，也不承诺把全来源核验变成只读当前页。
- 本批不解决不相关历史扫描、月度4500节点超限、首页调度、真实云端并发、媒体增长或备份恢复；这些仍属于后续B/C/D范围。

## 5. 改动边界和验收

预期产品增量仅涉及 `cloudfunctions/businessApi/lib/cloud-operations-field-repository.js` 与 `cloudfunctions/businessApi/lib/cloud-operations-repository.js`。复用现有域校验，不新建并行导出框架。补充对应仓储测试及A容量工具的合成场景/证据；不修改小程序页面、服务、配置、依赖、云函数入口或运营统计worker。若发现必须扩大产品文件范围，先说明原因和影响，不自行夹带重构。

| 验证面 | 必须通过的判定 |
| --- | --- |
| 输出一致 | 相同合成来源的v1/v2完整小报告，逐行逐列及顺序一致；覆盖单/多选、文本等其他字段、严格联动、不同分析筛选及历史显示名 |
| 查询投影 | 完整报告不读无关待审核列表；仪表待审核计数及旧导出保持原行为；相关审核来源故障仍拒绝导出 |
| 来源竞争 | 在基础报告异步阶段改变反馈值、反馈身份、审核轮次或票的增删替换，尾部核验拒绝；覆盖无审核、或签、会签 |
| 权限竞争 | 收集中、基础报告读取中、最终核验前停用/降权或改变售后权限，不返回旧授权内容；不跨请求复用授权 |
| 分页完整性 | 新增/删除候选及未匹配候选变化的检测不退化；基础来源变化拒绝续页；有效旧游标、冷/暖实例、缓存淘汰、过期、跨账号/查询游标分别验证 |
| 引用隔离 | 内部标识不进入响应、摘要、游标或报告缓存；仅完整导出使用；非导出统计/筛选/分析及刷新路径不增加读取或改变结果 |
| 开销对比 | 同样本、同预算记录逻辑读取数、返回文档数、事务数和最大操作数；测首个分页、暖续页、冷续页，不用减少核验事务冒充收益 |
| 完整回归 | 后端、客户端、operationsAnalytics及既有官方WXML/结构检查通过；检查产品文件摘要边界、差异、项目记忆，统一做一次最终独立复核 |

设计预期为无审核每个最终节点省2次事务外文档读取、有审核省3次，另减少未使用的待审核列表查询；本地实测已符合该结构预期，详见验收记录。150节点A样本每页1789→1488读，但2万读预算仍不足以完成整份报告；保留不完整结果，不调高预算混用前后数据宣称通过。

测量采用纯合成数据，无生产连接或业务写入；使用小规模完整报告核对内容，再分别测1/10/150节点及审核模式的读取收益，避免将大规模与所有维度相乘。关联规则保留2495行的小规模正确性样本。自动回归不代替五端原生或真实CloudBase事务/索引/性能验收，未执行者继续标记unverified。
