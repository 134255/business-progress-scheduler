# 定时任务可信来源修复设计

日期：2026-08-14

## 背景

真实 CloudBase Timer 已按控制台配置触发 `workflowReminder`，但连续调用均在业务服务运行前返回“提醒任务调用未经授权”。官方运行环境把定时来源写入服务端环境变量 `TRIGGER_SRC=timer`；当前实现却读取 `cloud.getWXContext().TRIGGER_SRC`。锁定版本的 `wx-server-sdk` 不会自动把该环境变量映射到微信调用上下文，因此合法 Timer 被失败关闭。

`calendarSync` 的计划入口使用了同样的错误读取方式。人工超级管理员同步通过一次性票据授权，不依赖该字段，已经能够正常工作。

## 采用方案

同时修复 `workflowReminder` 与 `calendarSync`：

1. 处理器通过可注入的可信来源读取器取得服务端来源；默认部署装配只读取 `process.env.TRIGGER_SRC`。
2. 只有来源严格等于小写字符串 `timer`，并且调用上下文不存在非空 `OPENID` 时，才允许进入计划任务路径。
3. 客户端或服务端传入的 `event.Type`、`mode`、`now`、批量大小以及 `getWXContext().TRIGGER_SRC` 均不参与授权。
4. `calendarSync` 的人工一次性票据路径保持不变；Timer 来源不能绕过非空人工票据的消费规则。
5. 来源缺失、大小写错误或类型错误时继续失败关闭，不执行服务、不写数据库。

## 影响范围

- 不修改业务流程、提醒算法、日历算法、数据库结构、索引、业务数据或现有触发器配置。
- 不影响 `businessApi`、人工日历同步或 `evidenceRetention`。
- 修复后仍需重新部署两个云函数；正式触发器继续保持为空，先用一次性 Timer 分别验收。

## 验证

- 真实可信来源 `timer` 可调用服务，并且只使用服务端时钟和固定批量。
- 仅伪造事件、仅伪造微信上下文字段、客户端带 `OPENID`、缺失来源和错误来源全部返回 `FORBIDDEN`，服务调用数为零。
- 人工日历同步票据仍一次性消费，失败仍使用安全错误边界。
- 运行两个云函数的完整测试，以及项目要求的后端、小程序、WXML、差异和记忆校验。
