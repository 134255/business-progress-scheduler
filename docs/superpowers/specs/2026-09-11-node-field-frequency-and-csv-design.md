# 节点字段选项次数与完整字段 CSV 设计

日期：2026-09-11

状态：产品范围、最终有效结果口径、角色权限及本文书面技术方案和导出排列已由用户确认，允许生成实施计划并开发。云端部署仍须独立验证。已验收的 CSV 生成/发送流程继续保留。

## 1. 已确认范围

- 运营看板按模板、节点、字段显示单选和多选各选项的出现次数。
- CSV 既能查看选项次数，也能查看各售后节点的字段明细。短文本、长文本、数字、布尔、日期不进入看板字段展示，但进入 CSV。
- 只统计已完成节点的最终有效结果；售后整体不必已完成。同一售后的同一节点字段只贡献一份结果，多选的每个选中项各计一次，不累计重复保存和已被驳回的旧轮次。
- 活动超级管理员查看全部符合条件的售后字段统计；普通活动账号仅统计当前有权访问的售后。CSV 继续只允许活动超级管理员导出，包括本次新增的完整字段明细。
- 不修改业务流转、历史反馈、审核、客户记录、账号关系、凭证访问或工时公式；不新增第三方分析服务。

## 2. 方案比较与推荐

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 每次查询直接遍历完成节点和审核/反馈 | 不增加统计存储，立即读权威结果 | 历史范围越大请求越慢，汇总与导出会重复解析 |
| 节点级选项派生快照，读取时重新授权（推荐） | 复用当前统计后台模式；避免重复解析；可补齐旧数据；可按当前权限精确计数 | 增加独立派生集合、游标和补齐状态；需验证后台预算 |
| 只存模板/字段全局累计数 | 全局查询快 | 不能可靠排除普通账号无权访问的售后，也难以处理撤权、重算和明细核对 |

采用第二种。选项快照与工时事实独立，不要求先完成日历补算，也不把现有工时的 generated 标记当成字段数据已生成。其他类型字段按导出需要从最终权威来源读取，不额外复制到统计集合。

## 3. 数据来源和计数规则

1. 先确认节点属于售后的实际路线。休眠、未走到、跳过和未完成节点不计数；逻辑删除售后不进入新增字段统计或字段明细，原基础运营导出行为不变。
2. 有审核节点取与节点最终通过轮次严格对应的不可变 fieldValues，并核对轮次状态、反馈编号/修订和处理轮次。无审核节点取已发布的 complete_node 反馈。不能笼统取任意“最新反馈”。
3. 流程模式 2 中处理/审核已完成、仅等待决定后续路线的节点，沿用当前完成分类：字段结果已最终确定，可以计数；未启动的追加节点不计数。
4. 日期范围按节点权威 completedAt 的上海自然日，首尾日期均包含，最多 366 天。缺少有效完成日期或无法证明最终结果的旧记录标为数据缺口，不猜测、不按零次计入、不修改历史记录。
5. 字段定义取售后实例快照，依据最终结果解析条件字段。隐藏字段、失效级联选项和未知字段不进入统计或字段明细；异常数据不得放宽校验后计数。
6. 分组身份为模板标识、稳定节点标识、稳定字段标识和字段类型，不按显示名称合并。跨版本仅合并类型、候选项和条件定义兼容的组；选项文字改变、候选项集合改变或条件定义改变时分组展示并标注版本。不同模板和不同稳定字段不混合。
7. 单选每份非空最终结果贡献一次；多选每个合法且唯一的选中项贡献一次。多选总次数可以大于填写样本数。空白不算选项，另外显示有效填写样本数和未填写样本数；数字 0 和布尔 false 在 CSV 中保留，不能当空白。
8. 合法但未被任何样本选中的候选项可显示 0 次；完全没有有效完成样本时显示“暂无有效样本”，区别于真实零次数。字段条件在最终结果下未显示的节点不进入该字段的填写样本分母。
9. 处理人筛选匹配最终提交该结果的处理人，审核人筛选匹配最终通过轮次中实际投票通过的人；两项同时指定时取交集，同一字段结果仍只计一次。不能将候选角色名单当作实际参与。

## 4. 数据流、权限与性能

- 新增仅云函数读写的 operations_field_snapshots，按节点确定性编号保存一份当前选项派生结果：模板/版本/稳定节点信息、完成日期、来源指针和摘要、兼容定义分组、单选/多选结果及内部筛选维度。不得包含自由文本字段、凭证地址、账号密码或微信身份。
- 来源摘要绑定字段定义、最终反馈或审核轮次与修订，不绑定会因日历补算变化的无关节点版本。读取源后，在发布快照前复核来源与完成分类；同源重试不增加次数，来源变化只能替换该节点快照，旧任务不能覆盖新来源。
- businessApi 增加独立字段统计/导出服务与仓储，不把新权限逻辑混入当前工时全局汇总。现有 getAnalyticsSummary、exportOperationsRows 及旧客户端协议保持兼容。
- 统计查询先按模板、日期和稳定节点筛选快照，再读取当前售后关系执行授权、当前状态和来源有效性检查，最后聚合；返回前再次核对账号活动状态及涉及的授权边界。普通账号不得收到被过滤售后的字段名、选项、计数、待补齐数量或可反推身份的信息。
- 统计接口只返回获授权后的分组计数和安全样本计数，不把每条售后的原始字段值送到普通客户端后再汇总。超级管理员的字段明细仍只通过专用受保护导出接口返回。
- 单次统计沿用最多 2,000 个节点样本、受控并发和有界读取；超过边界要求缩小日期或节点范围，不把前若干样本当完整统计。字段汇总与其 CSV 明细使用同一服务选择规则和来源集合。
- 新增完成事件只进行有界、可失败重试的派生刷新；统计失败不反转原业务完成成功。operationsAnalytics 增加独立字段恢复阶段，使用持久 keyset 游标扫描历史节点，每轮原始候选最多 40 条；无关或异常候选也推进游标，后续循环可重试。
- 不重置或重跑既有工时事实，不要求用户重新提交已完成售后。恢复阶段不占用原工时任务全部预算；给字段阶段设置剩余执行时间预算，原周期触发配置保持不变。实际时长必须在发布验收中验证。
- 字段快照只加速读取，不成为授权依据。缓存失配时可对已获授权的有限候选即时读取权威结果；超出单请求预算则明确返回“统计尚未补齐”。不得用部分结果生成标为完整的 CSV。
- 补齐状态依据历史扫描进度及目标查询范围内权威候选与有效快照的核对，而不是仅看快照集合。刚完成但尚无快照的节点也必须可被发现；未核对覆盖范围时不得宣称完整。
- 导出使用服务端认证的分页游标，绑定账号、筛选、来源版本及有效期。数据/角色在分页间变化时使本次导出失效并重试，不能拼接不同来源版本。新文件只在全部读取和校验成功后提供发送。

## 5. 看板交互

- 保留现有工时图表和全局工时可见性；增加“节点字段选项统计”区域，明确标注“按节点完成日期”和“全部售后”或“仅你有权限的售后”。
- 复用当前模板、日期、版本、节点、售后状态、具体售后及实际参与人筛选；单选/多选字段按节点顺序、字段顺序展示选项名称、次数和样本数，使用现有样式，不增加图表依赖。
- 字段筛选候选必须覆盖当前可授权的完成节点及其快照，不能只从已有工时事实推导。实例仍有合法快照的停用/已删除模板可按历史名称和版本识别；普通账号的新增字段候选也须先授权，不泄露其他售后的字段定义或选项。
- 当前日/周/月粒度继续控制原工时趋势；新增选项次数为所选日期范围的合计，不另加选项趋势功能。
- 统计加载、无样本、待补齐、范围过大和失败分别提示；字段统计失败不清空已成功加载的工时图表。账号、筛选或页面变更后丢弃旧请求结果。
- 不把文本、数字、布尔和日期字段值加载到看板用于隐藏展示；它们仅在管理员导出时读取。

## 6. 单个 CSV 的排列与兼容

实施补充（字符身份正确性）：原可读列仍使用既有公式保护与换行规范化；末尾增加“字段或选项原文（JSON）”。以此列解码精确原文并结合字段兼容组核对次数，避免含换行、引号或公式前缀的选项在导出后改变身份。该列不增加文件或操作入口；其他字段的导出原文也保存在此列。

继续使用一个“导出 CSV → 发送 CSV”按钮和一个文件，不增加第二个发送入口，也不把 CSV 当作支持多个工作表的格式。

保留现有基础运营列及其顺序，在末尾增加记录类型、筛选日期口径、模板/版本、字段标识、字段名称、字段类型、字段内容、选项内容、出现次数、有效填写样本数、未填写样本数和数据状态等列。文件包含三种可筛选记录：

| 记录类型 | 一行表示 | 日期口径 |
| --- | --- | --- |
| 运营基础 | 原有的一条售后节点运营记录，保持现有内容与筛选规则 | 售后创建日期 |
| 字段明细 | 一条已完成售后节点的一个可见字段最终值，附售后/节点编号用于追溯 | 节点完成日期 |
| 选项统计 | 一个模板/版本兼容组、节点、单选或多选字段下某选项的累计次数 | 节点完成日期 |

- 在界面导出说明与 CSV 日期口径列中明确区分两种日期，不能悄悄改变已验收的基础运营导出含义。字段明细与选项统计严格使用同一完成日期范围和当前字段统计筛选。
- 字段明细附原始字段类型与内容：文本完整保留，数字保持数值表达，布尔输出“是/否”，日期用 YYYY-MM-DD；单选输出选项文字，多选用 JSON 数组字符串保留各选项边界，避免选项自身含分隔符时无法还原。未填写保留空值并以数据状态标注。
- 字段明细不重复填写工时数值；选项统计行不冒充单条售后。用记录类型筛选后可分别查看基础工时、原始字段和次数汇总，避免重复相加工时。
- CSV 中的次数必须能够由同文件字段明细中的单选/多选值按对应兼容组重新计算得到。不能导出页面旧统计数再拼接新读到的字段。
- 沿用 UTF-8 BOM、RFC4180 引号/换行转义和公式注入防护；不静默截断文本。超过读取/文件安全预算明确失败并提示缩小范围，不提供残缺文件。
- 凭证二进制、下载地址、登录信息和内部授权令牌不是“其他字段”，不进入 CSV。导出到微信之外的目的地不在本次范围。

## 7. 验证与发布边界

先编写失败测试，再实施。验收至少包括：

- 单选、多选、空值、0/false、Unicode、逗号/引号/换行、公式前缀及同一多选值不可重复计数。
- 多次保存、驳回重提、重复完成回调、派生重试、后台与即时恢复并发均只保留一份最终结果。
- 有审核、无审核、等待人工决定后续、休眠/跳过/未走路线及无法核实的历史来源。
- 条件隐藏/级联、模板版本兼容与不兼容、相同名称不同稳定标识，以及旧模板已停用或删除但实例快照仍有效。
- 普通账号仅计授权售后、管理员全量、读取中撤权/停用/降级、伪造筛选/游标与缓存内容不得扩大权限。
- 老数据补齐、缺快照新节点、超过 40 条候选的公平推进、损坏来源不饿死后续节点、覆盖未完成不能伪报零次或完整。
- CSV 三种记录的日期口径、原列兼容、字段明细重新计算等于选项汇总、全部分页成功后才可发送、变更筛选/会话后旧文件不可复用。
- 全量 businessApi、operationsAnalytics、客户端、WXML 和项目记忆校验；用合成记录做集成与性能测试，不提交真实客户字段或文件。

发布预计涉及 businessApi、operationsAnalytics、小程序和新集合/查询索引。实现、代码验证与云端发布分开记录；新集合和索引创建、函数发布须按当次授权核对精确目标，保留现有函数权限、环境变量和 Timer 配置，不自动增加周期或清空数据。最后由用户在实际账号下核对同一筛选的看板次数与 CSV 明细，不能用部署成功代替验收。

## 8. 实施范围

- 后端：新增独立字段来源验证、派生、统计/导出服务与仓储模块；接入 businessApi 路由，复用现有动态字段与条件校验，避免复制出放宽校验的读取路径。
- 后台：为 operationsAnalytics 增加隔离的字段修复阶段与测试，不改变既有工时事实结构和可信 Timer 入口。
- 客户端：扩展 admin-operations 页面、业务服务及 CSV 编码装配测试；保留已验收发送状态机。
- 文档：更新部署/索引说明、验收用例和项目记忆；正式接受技术方案后再增加相应 ADR。

非目标包括自由文本词频、自动分类、人员排名、实时推送、Excel 多工作表、导出外部云盘、公开分享和重做现有工时分析。
