# 可选凭证与格式白名单一致性修复设计

日期：2026-08-13
状态：方案 A 已批准，待书面复核和实施

## 1. 问题与目标

真机验收已证明：节点快照为 `requiresEvidence: false` 且 `allowedEvidenceTypes: []` 时，小程序允许选择凭证，但服务端把空白名单解释为“禁止所有格式”，使凭证登记返回 `UNSUPPORTED_FILE_TYPE`。文件已上传到云存储，但 `evidences` 没有建立元数据记录。

本轮目标是统一模板、业务快照、小程序和服务端对可选凭证的理解，并兼容已创建的业务。

## 2. 规则

1. `requiresEvidence: true`：提交审核前必须至少关联一份有效凭证；`allowedEvidenceTypes` 必须为非空合法白名单。
2. `requiresEvidence: false` 且 `allowedEvidenceTypes` 非空：凭证可选，但仅允许白名单中的格式。
3. `requiresEvidence: false` 且 `allowedEvidenceTypes: []`：凭证可选，默认允许全部已支持格式：`jpg`、`jpeg`、`png`、`pdf`、`mp4`、`mov`、`m4v`。
4. 空白名单的“允许全部”语义只适用于非必传凭证；必传凭证仍不允许空白名单。

## 3. 实现边界

### 3.1 模板管理

- 将现有开关文案明确为“提交审核时必须上传凭证”。
- 无论开关是否开启，均可设置格式范围。
- 非必传状态下没有勾选格式时，显示“不限格式（仅限系统已支持格式）”的说明。
- 必传状态下没有勾选任何格式时，保持现有校验拦截。

### 3.2 小程序处理页

- 按相同三态规则计算有效白名单，不再将“非必传 + 空数组”理解为禁止上传。
- 保留已有的单图片 5MB、单 PDF/视频 20MB、单次反馈总量 20MB 与不限文件数量规则。
- 页面仍允许图片/视频和 PDF 选择，并在有限白名单下继续于本地拦截不允许的扩展名。

### 3.3 服务端

- 凭证登记权限、当前节点、处理人、真实文件字节、签名、扩展名和大小校验保持不变。
- 仅调整有效类型集合的推导：非必传且空白名单时使用全部支持格式。
- 非空白名单仍严格限制格式；非法结构、重复值或未知格式继续失败关闭。
- `UNSUPPORTED_FILE_TYPE` 在小程序中显示安全中文提示，不透出云文件编号、存储路径或底层错误。

## 4. 兼容与数据

- 已创建的 `requiresEvidence: false` + `allowedEvidenceTypes: []` 业务节点立即按新语义生效，不需要重建业务、批量改数据或修改编号。
- 已存在的非空白名单快照不受影响。
- 本次失败验收产生的无数据库记录测试云文件由操作员在确认不再需要后手动删除；本轮不扩展原始未登记云文件的自动清理协议。

## 5. 测试与验收

自动化必须先失败、再最小修复，覆盖：

- 非必传 + 空白名单允许全部七种格式。
- 非必传 + 非空白名单拒绝未勾选格式。
- 必传 + 空白名单仍被模板校验拒绝。
- 真实文件签名与扩展名不匹配仍被拒绝。
- 客户端选择、上传、登记与中文错误映射回归。

真机验收使用当前隔离业务：处理人重新选择不含敏感内容的 JPG 图片，确认上传后 `evidences` 建立元数据记录，“保存处理进度”成功，历史仅显示安全投影。

## 6. 不在本轮范围

- 不改变凭证 60 天保留与清理规则。
- 不改变文件数量、大小或真实内容校验。
- 不改变处理人、审核人、节点版本和业务状态重验。
- 不为未登记的原始云文件新增自动扫描或删除机制。
