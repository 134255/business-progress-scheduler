# 商品字段严格联动设计

日期：2026-09-18

状态：用户已确认本书面方案并明确要求直接修改；实施与审查进行中。实际测试、发布和模板配置状态以 docs/memory/STATUS.md 为准。

## 1. 目标与边界

仅配置用户指定的“45minup”模板中“售后信息收集”节点。保存前重新核对唯一模板、节点、版本和完整现有定义，不能仅凭同名节点选择目标。

- 删除该节点原 SKU 字段，保留其他无关字段、节点、角色、时限、凭证规则和路由。
- 分类、品牌、型号、属性1至属性5均为单选。分类仅包含灯具、人体工学椅、升降桌、儿童系列。
- 品牌同时受分类约束，型号同时受分类和品牌约束。各属性受分类、品牌、型号及所有前置有效属性共同约束，只允许源表中的完整组合。
- 型号没有的属性隐藏，E 至 I 的列身份不重排。例如只有 E、I 有值时显示属性1、属性5，不把属性5改名为属性2。
- 上级改变后，保留仍合法的下级选择，清除失效或隐藏的下级值；不清理无关字段或凭证。
- 本次不建立独立商品库、不改账号或访问权限、不增减集合/索引/Timer、不迁移或清理历史售后。
- 原始 Excel 只读使用，不修改、重算或连接其外部工作簿。

## 2. 已核对的数据来源

来源为用户桌面的《商品导入明细.xlsx》，仅取 Sheet1，不导入辅助工作表。

| 目标 | 来源列 | 处理 |
| --- | --- | --- |
| 分类 | L | 精确筛选四个指定类别 |
| 品牌 | D | 不猜测缺失品牌，不跨分类合并型号 |
| 型号 | B | 使用完整名称，不改变大小写或内部空格 |
| 属性1至属性5 | E、F、G、H、I | 非空值作为对应单选选项，空值表示该型号不适用 |

取单元格已保存的值，仅裁剪首尾空白，不做模糊归并。分类列含外部 VLOOKUP，部分其他列为同表引用；这些缓存值已读取，但不宣称已重新计算或验证外部工作簿。若源文件在配置前改变，必须重扫并重新生成候选配置。

当前只读核对基线：

- 365 行配件及 3 行非目标分类不在导入范围。
- 排除第 2185 行：缺少品牌；不根据属性文本推断品牌。
- 排除第 2859、2860 行：相同非空 SKU 编码对应不同型号，两行均暂缓，不任意选一行。
- 其余 2,495 行对应 2,495 个不同组合、229 个分类/品牌/型号组。
- 各类有效行/型号：灯具 57/19，人体工学椅 1,492/140，升降桌 903/60，儿童系列 43/10。
- 前一轮完整四类分析发现 37 个型号不能按属性独立笛卡尔积组合；不得将全量属性选项直接排列组合。

## 3. 方案选择

采用模板内置组合表。模板定义和创建后的节点快照保存同一份规则，选择时本地筛选，提交时服务端重新校验。

已考虑的替代方案：

1. 独立商品集合及查询接口：便于今后统一维护商品库，但增加数据、权限、网络和历史版本依赖，不属于本次范围。
2. 大量单父字段和重复隐藏字段：可表达部分路径，但会复制型号/属性、扩大字段数并拆散统计，不采用。

当前单父 `condition` 保持兼容；严格组合为显式新增规则，不把现有数据悄悄解释成新规则。

## 4. 存储契约与职责

### 4.1 组合规则

在该组第一个字段（分类）定义上保存可选 `optionLinkage`：

- `schemaVersion: 1`。
- `fieldKeys`：按分类、品牌、型号、属性1至属性5顺序列出八个稳定字段标识。
- `rows`：固定八列的合法组合；非空项为对应字段 `constraints.options` 数组的零基索引，属性不适用为显式 `null`。

选项原文仍由各字段的 `constraints.options` 保存，避免每行重复长文本。规则和字典必须整体规范化、整体保存，不允许单独重排字典而不重映射行。只有此组首字段持有矩阵，其他成员通过 `fieldKeys` 定位，避免每个属性重复保存完整组合表。

限定规则：

- 初版每节点最多一个商品组合组，八个成员均在本节点、标识唯一、类型为单选，顺序一致；首字段持有且列出自身。
- 前三列不可为空，属性列可以为空；同一分类/品牌/型号下各属性的存在状态须一致。
- 组合组成员不同时使用旧单父 `condition`，避免两个规则相互覆盖。其他字段原有条件保留，并允许按既有规则依赖前置组成员。
- 拒绝非法版本、稀疏数组、越界/小数/负数索引、重复行、未知引用、访问器、继承属性、危险对象键和跨节点引用。
- 产品级预算：最多 5,000 行；组合规则连同八列选项最多 256 KiB UTF-8 JSON；完整规范化节点最多 512 KiB UTF-8 JSON。它们是应用保护预算，不冒充云平台保证；发布前仍测量实际请求和数据库文档。
- 超限或损坏明确报错，不截断、不忽略规则、不降级为独立选择。

纯规则模块负责规范化、候选计算、清除失效值、最终组合验证和语义摘要。客户端和各服务部署副本采用同源实现或严格等价的一致性测试；模块不访问数据库、网络或用户身份。

### 4.2 定义、摘要和快照

- 字段规范化必须显式保留并验证 `optionLinkage`，模板定义摘要、节点快照、字段定义指纹和文本识别失效判定均覆盖组合语义。
- 缺少规则的旧字段保持原规范化结果及原摘要行为，不因新增空属性改变旧摘要。
- 模板保存和创建售后沿用已有权限、乐观版本、定义摘要和固定文档事务；禁止直接编辑 `template_nodes` 绕过模板头摘要。
- 新字段临时编辑标识先映射到服务端稳定标识，再重写组内引用；不能把 `_uiKey` 保存为权威字段标识。
- 模板复制生成新的字段标识并重写组引用；复制后的规则独立，不引用原模板字段。
- 历史售后读取自己的定义快照，不能回查新模板改变其候选、值或统计含义。

## 5. 填写与错误处理

按字段顺序筛选仍与已选前缀匹配的行。分类首先可选，选择后提供对应品牌，再提供对应型号。型号选定后知道需要哪些属性；按 E 至 I 的有效列依次开放选择，跳过不适用列。后续属性尚不可选时提示先选择前一项，不展示不合法的全量候选。

- 候选去重但保持源表首次出现顺序。仅剩一个候选仍由用户选择，不隐式提交或改变历史值。
- 分类、品牌、型号保留现有必填要求；新建的适用属性单选在最终提交时必填。保存处理进度仍支持合法但未填完的前缀，不能保存已经不合法的组合。
- 切换前缀后，从前到后重新计算；仍合法的选项保留，失效值清空，并继续传播到其后字段。
- `null` 只表示规则中的不适用属性，不作为用户可选的“空白 SKU”。隐藏字段不得进入提交、检索、统计分母或导出明细。
- 服务端在保存进度、提交审核、免审核完成及审计修订等现有字段写入口统一校验。最终结果必须对应一条完整合法行；客户端不能靠伪造选项绕过。
- 输入错误提示对应字段及需要重新选择的原因；网络/版本冲突与组合错误分开处理。并发模板变化时保留本地草稿，不覆盖他人的新版本。

前端全量组合保留在页面私有内存，`setData` 仅更新当前可见字段、候选和选择状态。切换选项不新增云请求；不把矩阵反复传入渲染层。

## 6. 模板编辑与本次配置流程

节点编辑页提供组合规则的结构化导入与摘要/预览：接受离线工具生成的 JSON，校验后展示有效组合数、字段顺序和联动试选。无需在小程序内解析 Excel，也不逐个手填数千条规则。导入只改变当前节点草稿，仍由已有模板保存操作提交。

- 组合组成员的候选和结构作为整体编辑，不走旧逗号文本拆分，避免选项内部逗号、换行等被拆坏。
- 单独删除组成员、改变其类型或顺序、以旧编辑器覆盖组规则必须被阻止并给出具体提示。整个规则替换需要新版显式保存意图和当前规则摘要，旧客户端不能无声丢掉规则。
- 没有组合规则的旧模板保持原编辑方式，不增加无关限制。
- 保留分类、品牌、型号现有稳定标识。属性字段使用新稳定标识；只删除已明确核对的 SKU 字段。
- 保存前检查 SKU 是否被卡片展示、其他条件或路由引用。如有引用，先列出影响并取得具体调整确认，不连带删除相关设置。
- 核对现有未保存草稿，防止热重载丢失用户编辑。若模板处于启用只读状态，需要按现有停用/保存/恢复启用流程执行，并在操作前明确告知短暂影响。
- 配置必须在运行时功能部署验证之后进行，不能先把新结构写入旧服务。
- 保存后重新读取已保存模板并核对规则摘要、字段标识、排除清单，以及未调整节点和字段的规范化投影一致。

## 7. 现有消费者兼容

| 模块 | 必需变化与边界 |
| --- | --- |
| 字段提交、工作区、卡片 | 统一解析当前可见字段及合法候选，保持原授权和字段值形态 |
| 模板新建/编辑/复制 | 保留组合规则，完整重写新字段引用；旧客户端保存不能丢规则 |
| 文本识别 | 当前代码仅检测旧 `condition`，需同时识别组合规则；仅发送当前可选择的字段及候选，确认写入后再次联动校验，不把完整商品矩阵发送给模型 |
| 统计与 CSV | 依据最终合法字段值计次；兼容分组摘要涵盖所在组的组合语义；候选使用最终前缀解析结果，不使用全量选项；隐藏属性不计为空样本 |
| 检索与分享 | 继续只投影已提交的有效字段值，不索引/公开未选择的商品目录或整个矩阵 |
| 流程分支 | 不扩展路由能力；组成员不作为新分支控制字段，保护现有路由不受配置删除影响 |

至少需更新 `businessApi`、`operationsAnalytics` 与小程序；其他函数仅在依赖审计及测试证明需要时更新，不因任务自动部署全部函数。统计派生继续失败隔离，不因派生失败反转业务成功。权限、环境变量和定时配置不变。

## 8. 验收要求

### 自动化

1. 对全部有效源行逐级验证：每一步原值在候选中，最终被服务端接受；枚举引擎所有完整可选路径，其集合与有效源组合完全相等。
2. 对多个非笛卡尔积型号构造独立选项合法但整体不存在的组合，客户端不提供且服务端拒绝。
3. 跨分类同品牌不串型号；相同属性文字不导致不同型号串联。
4. 属性中间空列正常跳过；上级改变清空失效下级并保留仍合法值、无关字段与凭证。
5. 保存合法不完整进度成功，最终提交缺少必填适用属性失败；隐藏属性提交失败。
6. 规则损坏、超限、非法引用、重复行、原型/访问器等输入全部失败关闭。
7. 新建与复制后的引用正确，旧模板摘要不变，规则改动使新摘要变化；重排字典并等价重映射行不改变组合语义摘要。
8. 旧客户端移除规则、不同版本并发覆盖、未读最新规则摘要的保存均被拒绝。
9. 统计、CSV、检索、卡片、分享和文本识别回归：只有实际值可见，规则不泄漏，原权限边界不变。
10. 本机使用真实数据仅做非持久化/未跟踪测试，仓库测试采用合成夹具，不提交真实商品表。

### 发布与页面验收

先本地通过自动化，再发布兼容云函数和小程序，最后通过正式模板编辑路径配置目标节点。模板保存之后刷新回读，并验证四个分类、多属性、中间空列、跨分类同品牌和不合法组合拦截。

页面响应测试记录首屏加载、选择切换和提交耗时；合成性能结果与真机结果分开。原有大列表性能不退化，不对未测量的设备承诺具体毫秒数。

不为验收擅自在生产创建新测试售后。若完整云端写入验收需要业务记录，应取得针对该测试记录的授权或使用隔离环境；纯联动预览、模板保存回读与本地提交测试先完成。

在新规则已被实际业务引用后，不回滚到会丢弃规则的旧版本。部署失败先停止配置，不保留半份组合表；回滚模板须走现有版本校验及正式保存流程，不能直接恢复陈旧模板头。
