# CloudBase 固定文档不存在处理设计

## 背景

首次打开账户登录页时，`getSession` 会按当前可信微信身份的 SHA-256 摘要读取 `wechat_bindings` 固定文档。尚未绑定的身份没有对应文档。测试数据库此前把缺失文档表示为 `{ data: null }`，但真实 CloudBase 的 `document.get()` 会抛出包含 `document.get:fail` 和 `does not exist` 的异常。仓库读取层未统一这两种语义，导致正常的“未绑定”状态被当作登录错误，初始化入口无法显示。

## 目标

- 将真实 CloudBase 的明确“固定文档不存在”结果转换为仓库层的 `null`。
- 保持权限错误、网络错误、参数错误和其他数据库错误原样失败，不能把真实故障伪装成未绑定。
- 让测试数据库复现真实 CloudBase 的缺失文档行为，防止回归。
- 不改变账户事务、初始化守卫、OpenID 绑定规则或客户端接口。

## 方案

在 `cloud-account-repository.js` 的统一 `readDocument` 边界增加一个窄范围判定：仅当异常文本同时表明 `document.get:fail` 和目标文档 `does not exist` 时返回 `null`；其他异常继续抛出。

测试用假数据库的 `doc(id).get()` 在文档缺失时改为抛出与真实 CloudBase 同类的错误。这样所有通过 `readDocument` 的固定文档读取都会验证统一转换逻辑，事务内固定文档读取仍保持现有架构，不改成查询。

## 数据流

1. 小程序调用公开路由 `getSession`。
2. 云函数从微信运行时取得可信 OpenID，并计算绑定文档 ID。
3. `readDocument` 读取 `wechat_bindings/<digest>`。
4. 文档不存在时，仓库返回 `null`；认证服务继续读取管理员守卫。
5. 守卫计数为零时返回 `authenticated: false` 和 `requiresInitialization: true`，登录页显示初始化入口。

## 错误与安全边界

- 只吞掉语义明确的缺失文档异常。
- 权限拒绝、集合不存在、网络失败、超时和未知异常继续上抛。
- 不记录或展示 OpenID、摘要、恢复码、密码或挑战令牌。
- 不创建占位绑定记录，不扩大数据库写入面。
- 不改变 `wechat_bindings/<sha256(openid)>` 的唯一性权威。

## 测试与验收

采用 TDD：

1. 先让假数据库对缺失固定文档抛出真实风格异常，并运行聚焦测试，确认当前实现失败。
2. 增加仓库读取层的最小转换逻辑，确认聚焦测试通过。
3. 增加或保留测试证明非缺失错误不会被吞掉。
4. 运行后端全套测试、客户端账户测试、WXML 检查、语法检查、差异检查和项目记忆校验。
5. 部署后重新编译小程序；未绑定且系统未初始化时必须显示“初始化首位管理员”，且控制台不再出现缺失绑定文档错误。

真实 CloudBase 与微信开发者工具验收在操作员执行前继续标记为 `unverified`。
