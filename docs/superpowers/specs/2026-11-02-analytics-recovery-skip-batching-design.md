# 运营字段补算：连续无须生成节点的小批游标优化

日期：2026-11-02。状态：用户已确认短设计及实施计划；本地实现、回归和独立复核完成，后续单独授权的单文件云部署/完整读回亦已完成。实际现金未验，证据见 docs/deployment/analytics-recovery-skip-batching-acceptance.md。

## 目标与边界

降低 `operationsAnalytics/lib/field-snapshot-recovery.js` 遍历连续无须生成字段统计节点时的游标读写。只调整该 worker 和对应测试；不改变售后内容/进度、站内通知、企微规则、客户端、权限、集合或索引、定时配置、统计快照格式及对外返回字段。

“无须生成”限于旧 `loadSource` 的节点状态/路线排除条件，例如未完成、休眠或跳过节点。已完成且已有相同快照的节点仍保留完整权威来源校验；本轮不优化那类复查，也不以缓存摘要代替来源证明。创建中/删除售后等须读取售后头才能判断的排除情况不纳入本快路径。

## Approaches：已讨论的取舍

- **用户选择：保守小改。** 合并连续明确不符合生成条件节点的游标操作，保留正常补算、原始节点遍历和全量回绕。无新状态或付费资源，收益局限于此类连续节点。
- **暂不采用：变化节点队列加低频全量恢复。** 可进一步减少已完成节点的重复复查，但需要新的变更登记、遗漏恢复和额外写入设计，不属于本轮。

## 小批处理

以下最多8条/组是实施建议值，并非用户此前指定的数字。

1. 仍按原查询取最多40条、按 `_id` 递增的原始页，5秒协作预算不变。不追加查询或把省下的预算用于扩大本轮覆盖。
2. 每组首个节点仍走原来的单条流程：先用现有 CAS 保存其游标，再执行原 `loadSource`/必要时发布。只有它已处理且没有来源、原页提示可安全排除时，才考虑合并紧随其后的同类节点。
3. 从当前页收集最多7个连续排除候选；至少有2个后续候选才启动合批，避免单节点额外探测。候选只是提示，不是跳过当前状态校验的依据；属性访问器、异常原型、损坏或非单调编号不进入快路径。
4. 在一个事务内重新读取当前游标并验证原版本/位置，逐个固定文档重读候选节点。仅按旧节点排除规则确认的连续前缀可推进；节点变成可生成、结构异常或不能确定时，在它之前停止，未确认节点回到原单条流程。缺失节点沿用旧的“不生成”语义。
5. 对已确认前缀只写一次原游标，版本仍递增且 CAS 不变。只有确认到原始短页真正末尾时才回到空游标；不能因小组结束就回绕。原整页40条后的空页回绕逻辑不变。
6. 合批返回的消费数和下一游标必须来自已成功提交事务。CAS 失败停止本轮；数据库、写入或提交结果未知时不把小批拆成单条重放，不推进未确认节点。SDK 原有冲突重试每次重新读取、重新建立前缀，不跨重试保存判断。
7. 合批预算耗尽时回滚该批并结束本轮，不在截止后另发检查点写入。组首原检查点已经保存，下一轮从其后继续，因此即使后续小批一直遇到慢读取，也不会每次从相同组首重新开始并永久饿死后面的节点。已在途 SDK 调用不可取消，实际云端时限仍须单独核实。

## 预期收益与不承诺事项

既有纯本地基线：30个连续未完成节点每轮61个成功固定文档读取、1次查询、30次游标写和30个事务。按上面的8条组上限，稳定且无冲突/超时的场景目标为39读、1查询、8写、8事务；此为待测试目标，不是实现结果、云计费次数或节省报价。

单节点/零节点/全部可生成节点应保持原路径成本；混合状态、并发变化及合批被中断可能产生额外已知探测读取，需如实量化，不承诺每种输入均降本。30个已完成且快照未变节点的原241读/60事务场景不作为本轮已优化项。
