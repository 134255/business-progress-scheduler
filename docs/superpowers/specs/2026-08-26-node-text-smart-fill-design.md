# 当前节点文本智能识别与字段预填设计

日期：2026-08-26
状态：已完成产品与技术设计，等待项目所有者书面复核后生成实施计划

## 1. 背景与目标

节点处理人经常从微信或其他来源收到一段半结构化文本，再逐项填写当前节点的型号、购买日期、仓库、订单号、客户姓名等动态字段。重复抄录慢且容易填错。

本功能在当前可编辑节点的处理页新增一个“粘贴文本智能识别”区域。处理人粘贴文本并主动点击“智能识别”后，系统只把该段文本和当前节点字段定义交给托管 AI 模型，返回字段候选值；用户必须在预览中确认，系统才把勾选结果写入页面表单。真正持久化仍沿用既有“保存处理进度/提交审核”入口。

目标：

- 减少从聊天文本到结构化字段的重复录入。
- 只处理当前节点，不跨节点、不修改历史、不绕过原有授权和版本控制。
- AI 只提供候选，不替用户保存、提交或改变节点状态。
- 原始粘贴文本不进入数据库、日志、审计、项目记忆或搜索索引。
- 复用 CloudBase 托管能力，第一版不引入外部厂商密钥。

非目标：

- 不从图片、PDF、视频或凭证中 OCR/抽取内容。
- 不自动创建字段、选项或改变模板。
- 不在后台监听剪贴板，不在用户未点击时调用 AI。
- 不自动覆盖已有字段，不自动保存处理进度，不自动提交审核。
- 不跨售后、跨节点或读取其他轮次内容推断当前字段。

## 2. 用户流程

1. 活动处理人进入自己当前可编辑的节点。
2. 页面显示“粘贴文本智能识别”折叠区和多行文本框；文本最多 8,000 个字符。
3. 用户粘贴文本并点击“智能识别”。页面显示单一加载态，当前账号同一时间只允许一个识别请求。
4. 服务端重新校验账号、售后、当前节点、处理人关系、节点状态、节点版本和字段定义。
5. AI 返回后，客户端展示三个分组：
   - 可直接填入：空字段且结果通过严格类型校验。
   - 可能替换：字段已有值，默认不勾选，必须由用户逐项选择是否替换。
   - 需要人工确认：低置信度、歧义日期/单位、候选接近或无法可靠匹配。
6. 每项显示字段名称、候选值、识别置信度和一小段来源摘录；不显示模型思维过程。
7. 用户点击“应用所选结果”后，仅更新当前页面表单。用户取消、离开页面或清空文本后，原始文本与未应用结果消失。
8. 用户继续使用既有保存或提交入口；既有必填、长度、类型、凭证、版本和审核规则全部照常执行。

## 3. 总体架构

采用“受保护 API + 独立解析工作器”的结构：

```text
小程序节点处理页
    -> businessApi.recognizeNodeText
       -> 当前账号/售后/节点/版本/字段定义授权
       -> 限流与单飞锁
       -> 签发五分钟一次性内部票据
       -> 服务端调用 nodeTextParser
          -> 原子消费票据并校验摘要
          -> CloudBase AI+ 托管模型
          -> 严格 JSON 解析、类型与选项白名单校验
       -> businessApi 再次授权并验证版本/字段定义未变化
    <- 仅返回安全候选
```

### 3.1 `businessApi.recognizeNodeText`

客户端输入固定为：

```json
{
  "businessLineId": "...",
  "nodeId": "...",
  "expectedNodeVersion": 1,
  "text": "...",
  "requestKey": "..."
}
```

入口剥离任何客户端身份、角色、模型、提示词、字段定义、票据和置信度阈值。服务端从权威节点快照生成字段定义，只允许当前活动处理人对当前 `ready/in_progress` 新版节点发起识别；停用账号、旧节点、待审核、已完成、取消、关闭、删除或非当前节点均拒绝。

### 3.2 `nodeTextParser`

新增独立 CloudBase 云函数 `nodeTextParser`。它不向小程序开放业务入口，只有持有合法一次性票据的服务端调用可以进入模型编排。函数通过适配器调用 CloudBase AI+ 内置托管模型，默认使用项目部署时确认的可用混元或 DeepSeek 模型；模型名称来自服务端配置，客户端不能选择。

CloudBase AI+ 官方 Node.js 接入支持托管混元和 DeepSeek 模型，内置模型不需要项目另行保存第三方 API Key；部署时仍需核对目标环境套餐、Token 配额、模型可用性和至少 60 秒函数超时：

- <https://cloud.tencent.com/document/product/876/130727>
- <https://docs.cloudbase.net/ai/model/nodejs-access>
- <https://docs.cloudbase.net/api-reference/server/node-sdk/ai>

适配器隔离厂商请求与响应形状，后续如需切换模型，只修改服务端适配层和配置，不改变客户端协议、授权或字段候选协议。

## 4. 一次性内部票据为何必要

如果小程序能直接调用 `nodeTextParser`，或解析函数只相信事件里的账号、节点和字段定义，那么知道函数名的人就可以绕过 `businessApi`，伪造字段、重复消耗模型 Token，甚至把该云函数当公共 AI 代理使用。

票据把一次 AI 调用绑定为服务端已经批准的最小能力：

- 至少 192 位不可预测随机编号。
- 绑定当前账号、售后编号、节点编号、期望节点版本、字段定义摘要、原文摘要和稳定请求键摘要。
- 五分钟有效，只能从 `pending` 原子变为 `consumed` 一次；过期、重放、摘要不一致或结构损坏均失败关闭。
- 票据文档不保存原始文本、字段值、显示名、OpenID、永久文件编号或模型结果。
- 票据不会显示给用户，不参与业务数据、通知、审计、搜索或运营统计。

因此“票据伪造测试”验证的是安全边界，而非一项面向用户的功能：测试需要证明随机编号不可替代授权、过期票据不可用、已消费票据不能重放，以及文本、字段定义、节点版本或账号任一变化都会被拒绝。

## 5. 数据结构与限流

新增仅云函数读写集合：

### 5.1 `node_text_parse_requests`

保存短期票据和最小状态：

- `_id`：随机票据编号。
- `requestKeyHash`、`actorHash`：不可逆摘要。
- `businessLineId`、`nodeId`、`expectedNodeVersion`。
- `schemaDigest`、`textDigest`。
- `status: pending | consumed | failed`。
- `createdAt`、`expiresAt`、`consumedAt`、`revision`。

不保存 `text`、字段候选、模型原始响应或用户身份原值。过期票据通过 `expiresAt ASC, _id ASC` 索引在普通解析调用中每次最多机会式清理 20 条；第一版不配置定时触发器。

### 5.2 `node_text_parse_usage`

每个账号一个确定性摘要文档，保存当前分钟窗口计数、当日计数、短期单飞锁令牌、锁到期时间和乐观修订。限制为：

- 同一账号最多一个在途识别请求。
- 每分钟最多 10 次。
- 每个上海自然日最多 100 次。
- 损坏计数、时间回退、修订上溢或锁结构异常均失败关闭。

该集合不保存粘贴内容或模型结果，也不产生按分钟增长的文档。

## 6. 传给模型的数据最小化

模型只接收：

- 用户本次主动提交的粘贴文本。
- 当前节点经过服务端规范化的字段列表：稳定字段键、名称、类型、必填标记、长度/数值/日期约束以及单选/多选允许选项。
- 固定系统指令和严格输出 JSON Schema。

不发送当前账号、售后名称/编号、客户以外的业务元数据、其他节点、反馈历史、审核意见、凭证、文件路径、模板成员、处理人、审核人、OpenID 或请求键。

粘贴文本一律按不可信数据处理；其中要求“忽略规则”“输出其他字段”“访问凭证”等内容都只能作为待抽取正文，不能改变系统指令。

## 7. 字段识别与规范化规则

模型只能返回当前字段键，服务端必须再次逐项验证：

- 短文本/长文本：遵守既有长度、必填和字符约束。
- 数字：必须能严格解析为安全数值；单位不明确、范围表达或多个候选进入人工确认。
- 日期：只接受能无歧义规范化为 `YYYY-MM-DD` 的日期；缺少年份、相对日期或多个解释进入人工确认。
- 布尔：只接受明确肯定/否定语义；含糊表达不自动填入。
- 单选/多选：只能从当前字段已有选项中选择，不得创造新选项。
- 凭证：不识别、不上传、不关联。

未知字段键、重复字段键、稀疏数组、访问器/继承属性、未知对象字段、超长摘录、非法类型、非有限置信度、选项外值或响应超限全部拒绝整份模型结果，并返回固定中文错误。

### 7.1 单选与多选模糊匹配

用户确认允许单选、多选使用模糊语义匹配：

- 先做规范化精确匹配；精确命中优先级最高，置信度视为 100%。
- 未精确命中时，模型只能对现有选项排序并给出 `0..1` 的匹配置信度。该值是模型匹配分，不宣称为统计学概率。
- 阈值为 50%。低于 0.5 的选项不能成为自动候选。
- 单选只取最高分选项；若最高分低于 0.5，或前两名差值小于 0.1，则进入人工确认，不默认勾选。
- 多选保留所有不低于 0.5 的现有选项，并按置信度从高到低展示；空字段可以在预览中默认勾选，已有字段仍默认不替换。
- 服务端使用规范化选项文本和稳定选项值二次核验，禁止模型返回未定义选项。

## 8. 输出协议与客户端预览

解析工作器只返回有界候选：

```json
{
  "schemaDigest": "...",
  "nodeVersion": 1,
  "candidates": [
    {
      "fieldKey": "model",
      "value": "A1",
      "confidence": 0.92,
      "matchKind": "semantic",
      "sourceExcerpt": "型号 A1",
      "requiresConfirmation": false,
      "warnings": []
    }
  ]
}
```

客户端不信任响应本身，应用前仍按页面现有字段定义重新验证字段键和类型。预览中的已有值替换项默认不勾选；任何识别结果都不能直接触发 `saveNodeProgress` 或 `submitNodeForReview`。

## 9. 并发、幂等与失败恢复

- 客户端为每次用户动作生成稳定 `requestKey`，并绑定账号、页面请求序号、节点编号、期望版本、字段定义摘要和本地表单修订。
- 识别期间用户可取消；账号切换、页面离开、节点版本变化、字段定义变化或用户继续手工修改表单后，迟到结果必须丢弃。
- `businessApi` 在模型返回后再次读取活动账号、售后、当前节点、处理关系、版本和字段定义摘要；任一变化均不返回候选。
- 相同请求的响应丢失后不持久化模型结果，以满足原文和结果最小化；再次识别可能重新消耗一次额度，这是明确的隐私优先取舍，分钟/日限流控制成本上界。
- AI 超时、配额不足、模型不可用、格式错误、解析失败和底层数据库错误统一映射为固定中文提示，例如“智能识别暂时不可用，请稍后重试”；客户端不得展示供应商错误、模型原文、堆栈、云路径或请求编号。

## 10. 日志、审计与安全

- 日志只记录安全错误分类、耗时区间、候选数量和是否命中限流，不记录原文、候选值、字段名称、身份、售后/节点编号、票据或模型响应。
- 业务审计只在用户随后真正保存进度时沿用既有审计；单纯识别和预览不写业务审计正文。
- 项目记忆、任务报告和 Git 不保存真实粘贴文本、模型结果、账号或客户数据。
- 模型配置、配额和费用告警在 CloudBase 控制台管理；客户端不可覆盖模型或提示词。

## 11. 部署与索引

部署新增：

- 云函数 `nodeTextParser`，仅服务端票据调用，超时至少 60 秒，首次触发器固定为 `[]`。
- 集合 `node_text_parse_requests`、`node_text_parse_usage`，均仅云函数读写。
- 索引 `node_text_parse_requests(expiresAt ASC, _id ASC)`。
- CloudBase AI+ 模型配置、Token 配额与费用告警。

`businessApi` 需重新部署，小程序需重新上传。部署时不得把模型密钥、原文样例或身份值写入代码、环境变量截图、文档或 Git。真实模型可用性、CloudBase 嵌套调用上下文、费用、延迟、并发、集合权限、索引选择和真机预览均属于部署后人工验收边界。

## 12. 测试与验收

自动化至少覆盖：

- 权限：非处理人、停用账号、非当前节点、待审核/完成节点、旧节点、伪造身份字段均拒绝。
- 票据：随机性、五分钟过期、单次消费、重放、账号/节点/版本/schema/text 摘要篡改、损坏结构均拒绝。
- 限流：单飞锁、10 次/分钟、100 次/日、跨上海自然日重置、计数损坏和并发争抢。
- 模型边界：超时、配额、非 JSON、未知字段、重复字段、超长、提示注入文本、非法类型和访问器/继承结构。
- 字段类型：文本、数字、日期、布尔、单选、多选以及必填和长度约束。
- 选项：精确匹配优先，0.5 阈值，最高分优先，单选接近候选人工确认，多选排序和禁止新选项。
- 客户端：三组预览、已有值默认不覆盖、取消、页面离开、账号/版本/schema/手工编辑变化后丢弃迟到响应、固定安全错误。
- 隐私：数据库、日志、审计、通知、搜索索引和运营事实均不出现原始粘贴文本或模型候选。

人工验收使用无敏感测试文本，依次验证空字段填入、已有值不覆盖、单选/多选模糊匹配、错误提示、取消、网络超时、账号切换和最终保存；不得用真实客户资料做首次模型验收。

## 13. 完成标准

- 用户能在当前节点粘贴文本、主动识别、预览并选择应用字段。
- 未确认的候选不进入表单；未保存的候选不进入数据库。
- 当前授权、节点版本和字段定义变化时，结果安全失效。
- 票据不可伪造、不可重放且不保存原文。
- 模型只看到最小输入，日志与持久数据不泄漏原文或结果。
- 模糊单选/多选严格限制在已有选项并执行 50% 阈值。
- 全量自动化门禁通过，真实 CloudBase 与真机边界被明确记录为已验证或 `unverified`。
