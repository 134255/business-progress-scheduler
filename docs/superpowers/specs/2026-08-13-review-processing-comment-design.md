# 审核处理说明不可变快照设计

## 背景与问题

真实隔离验收确认：处理人保存进度时填写的说明仍存在于已发布 `node_feedback.comment`，但提交审核后，审核详情只显示字段快照和凭证，没有显示该说明。根因不是数据丢失，而是审核提交链路只把字段和值、凭证编号及字节数聚合进审核草稿和 `node_review_rounds`，遗漏了最新反馈说明；审核详情安全投影和页面自然也无该字段。

## 已选方案

采用不可变审核轮次快照。聚合当前处理轮草稿时，从最新已发布反馈读取说明并规范化为 `processingComment`；该值进入草稿摘要和输入摘要校验，审核轮次创建时固化保存，审核详情通过安全投影返回，页面以只读“处理说明”展示。

不采用审核详情实时回查 `node_feedback`：实时回查会增加查询和授权复杂度，并让历史审核内容受后续记录变化影响。不采用仅在客户端拼接：客户端无法构成服务端不可变审计事实，导出和其他安全查询也仍会缺失。

## 数据与接口

- 草稿对象新增 `processingComment: string`，来源只能是当前处理轮最新已发布反馈的自有数据属性 `comment`。
- 合法说明必须是字符串，按现有反馈保存规则最大 1000 个字符；缺失、访问器、继承值或超限结构在新审核提交时失败关闭，不从旧记录或客户端回退。
- `hashDraft` 与仓储的 `validateDraft` 都纳入 `processingComment`，防止聚合后到事务落库前说明发生变化。
- `node_review_rounds` 新增不可变 `processingComment`；创建后不允许投票或补算流程改写。
- `getReviewDetail` 返回安全字段 `processingComment`。新轮次必须持有合法字符串；旧轮次确实缺失该字段时兼容返回空字符串，不实时回查反馈。
- 小程序审核详情在字段快照之前展示“处理说明”；空字符串显示“暂无处理说明”。说明仅只读，不进入审核意见输入框。

## 安全与兼容

- 不返回原始请求键、内部摘要、云文件编号、OpenID 或账号关系数组。
- 不修改现有 `node_feedback`、凭证归属、审核投票、双 SLA、节点版本或 60 天保留协议。
- 现有已经创建且缺少 `processingComment` 的审核轮次保持可读，显示安全占位；不执行数据迁移。
- 当前真实审核轮次是在修复前创建，部署后仍按旧轮次显示占位。要验证新快照，需要使用隔离业务执行一次新的处理轮提交；不得手工修改现有审核轮次。

## 验证

1. 反馈仓储聚合测试证明最新反馈说明进入草稿，访问器、继承值和超限结构失败关闭。
2. 审核服务测试证明说明进入草稿摘要；说明变化会改变摘要。
3. 审核仓储测试证明创建轮次保存说明、事务校验说明，详情安全投影返回说明，旧轮次缺失时返回空字符串。
4. 小程序测试和 WXML 结构测试证明说明只读展示及空值占位。
5. 运行四个云函数、小程序和 WXML 全量回归；真实部署后以新审核轮次复验。
