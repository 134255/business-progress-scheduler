# 首位超级管理员安全初始化页面设计

日期：2026-08-06
状态：已批准，尚未实现

## 背景

账户管理后端已经提供公开路由 `initializeSuperAdmin`，并通过可信微信 OpenID、零活动超级管理员守卫、一次性恢复码哈希和数据库事务限制初始化只能成功一次。原部署手册要求操作员使用微信开发者工具的云函数云端测试面板调用该路由。

当前微信开发者工具 Stable 2.01.2510290 在云函数右键菜单中只提供本地调试，没有原手册假设的云端测试入口。本地调试不等同于调用目标环境中的已部署函数；CloudBase 控制台模拟测试也不能作为可信小程序 OpenID 的来源。为了继续安全初始化，需要由小程序运行时发起 `wx.cloud.callFunction` 调用。

## 目标

- 仅在系统尚无活动超级管理员时，为部署操作员提供可发现的初始化入口。
- 从小程序运行时调用已部署的 `businessApi`，使后端取得可信微信 OpenID。
- 初始化成功后自动使用临时密码登录，并进入现有的强制改密流程。
- 确保临时密码、确认密码和恢复码不进入存储、全局状态、页面参数、数据集、日志或错误信息。
- 保留后端守卫、恢复码消费和事务作为唯一安全边界。

## 非目标

- 不提供超级管理员紧急恢复页面；紧急恢复仍按受控维护流程执行。
- 不改变密码规则、恢复码格式、数据库集合或后端事务不变量。
- 不自动保存、生成或展示任何账号密码或恢复材料。
- 不把页面隐藏或路由不可发现性当作安全控制。

## 方案比较与决策

### 方案 A：独立初始化页面（采用）

登录页检测到 `requiresInitialization` 后隐藏普通登录表单，并显示“初始化首位管理员”按钮。按钮进入独立初始化页面。该方案使普通登录和一次性初始化的状态、敏感字段清理及测试边界相互独立。

### 方案 B：登录页内切换初始化表单

文件较少，但登录、初始化、自动登录和多组敏感字段共用一个页面状态，增加误留字段和回归风险。

### 方案 C：隐藏的开发专用路由

表面改动最少，但依赖手工输入页面路径，部署操作容易遗漏，再次引入工具和人员记忆依赖。

采用方案 A。

## 页面和导航

新增 `pages/admin-initialize/index`，并注册到 `miniprogram/app.json`。

登录页行为：

1. `getSession` 返回 `requiresInitialization: true` 时，隐藏用户名和密码登录表单。
2. 显示清晰的未初始化说明和“初始化首位管理员”按钮。
3. 按钮只导航到初始化页面，不携带任何参数。

初始化页面行为：

1. 页面加载时再次调用 `getSession`。
2. 如果会话已认证，跳转仪表盘；如果不再需要初始化，返回登录页。
3. 只有再次确认 `requiresInitialization: true` 后才显示表单。
4. 表单字段为管理员用户名、显示名称、临时密码、确认临时密码和纸质恢复码。
5. 临时密码、确认密码和恢复码均使用掩码输入。

## 提交数据流

1. 客户端检查必填项、临时密码与确认密码一致，并阻止重复提交。后端仍负责最终密码规则和权限判定。
2. 页面调用账户服务的 `initializeSuperAdmin(username, displayName, temporaryPassword, recoveryCode)`。
3. 账户服务通过静默 `callBusinessApi` 调用 `initializeSuperAdmin`，不产生包含输入数据的 Toast 或日志。
4. 初始化成功后，页面使用仍在当前调用栈内的用户名和临时密码调用现有 `login`。
5. `login` 必须返回 `passwordChangeRequired` 和挑战令牌。页面立即清空临时密码、确认密码和恢复码，将挑战令牌仅写入 `getApp().globalData.loginChallenge`，然后导航到现有 `pages/change-password/index?mode=first`。
6. 正式密码设置成功后沿用现有流程绑定会话并进入仪表盘。

页面不自动保存用户名或显示名称。页面卸载时清空全部表单字段。

## 异常处理

- 初始化调用失败：清空临时密码、确认密码和恢复码；保留用户名与显示名称方便纠错；显示后端的脱敏错误消息。
- `ALREADY_INITIALIZED`：清空全部字段并返回登录页，不继续调用初始化。
- 初始化已经成功但自动登录失败：立即清空敏感字段，绝不再次调用初始化；用不可取消提示告知“管理员已创建，请返回登录页使用临时密码登录”，随后返回登录页。
- 自动登录返回非预期成功形态：按自动登录失败处理，不保留恢复材料。
- 页面重复提交：提交期间禁用按钮，仅允许一个初始化调用在途。
- 页面卸载：清空用户名、显示名称、临时密码、确认密码和恢复码。

## 安全约束

- 后端的可信 OpenID、`activeSuperAdminCount === 0`、环境变量哈希、守卫哈希、`recoveryConsumedAt` 和事务消费仍是唯一授权条件。
- 客户端不得接受或发送 payload OpenID。
- 不调用 `wx.setStorage`、`wx.setStorageSync` 或其他持久化 API 保存表单值或挑战令牌。
- 不把表单值放入 URL、dataset、页面栈参数、埋点、日志、审计快照或异常消息。
- 不在 UI 中提供复制恢复码或密码的功能。
- 初始化成功后的恢复码已经消费，不得复用；后续恢复必须轮换新恢复码和两处哈希配置。

## 测试设计

实施遵循测试驱动开发，至少覆盖：

- 账户服务以静默调用发送正确的初始化动作和四个业务字段，不发送 OpenID。
- 登录页仅在 `requiresInitialization` 时显示并触发初始化入口导航。
- 初始化页面加载时重新核对会话和初始化状态。
- 必填项缺失或两次临时密码不一致时不调用后端。
- 成功初始化后自动登录，挑战令牌只写入应用内存，并进入强制改密页。
- 敏感字段在初始化失败、自动登录失败、成功跳转前和页面卸载时清空。
- 初始化成功但自动登录失败时不会第二次调用初始化。
- `ALREADY_INITIALIZED` 返回登录页。
- WXML 条件分支结构有效，页面不通过 dataset 或导航参数携带敏感值。

## 手工验收

1. 部署当前 `businessApi`，并确认恢复哈希的云函数环境变量和守卫字段均已配置且一致。
2. 在模拟器登录页确认未初始化提示和初始化入口出现。
3. 由操作员本地输入真实账号资料、临时密码和纸质恢复码；不截图、不保存原始调用。
4. 确认初始化后自动进入强制改密页，并完成正式密码设置。
5. 仅核对脱敏状态：活动超级管理员数为 `1`、恢复状态已消费、凭据不再要求改密、微信绑定保留和初始化审计记录存在。
6. 重新进入登录页，确认初始化入口不再出现。
