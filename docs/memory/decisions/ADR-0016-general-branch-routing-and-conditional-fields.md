# ADR-0016：通用单线分支路由与条件字段

## Status

已于 2026-09-03 接受设计，尚未实施。

## Context

现有模板只能顺序推进，并以唯一末尾 `optional_tail` 表达一次人工追加。单选字段只有固定选项，不能控制当前节点后续字段或下一节点。业务需要任意节点产生分支、分支后继续分支、互斥路线重新汇合，以及父单选驱动字段显示和级联候选项。同时，“售后发起人作为唯一处理人”需要改为可与固定处理人并存。

继续扩展 `optional_tail` 特殊逻辑会使完成、审核、提醒、检索、分享和统计产生更多不一致分支；引入独立工作流平台则会增加当前阶段不必要的服务、权限和费用边界。

## Decision

- 在现有 `businessApi` 内建立统一的流程模式版本 2 无环路由引擎，不新增外部工作流服务。
- 模板保持最多 48 个节点、唯一入口、全部可达和无循环；允许嵌套与重新汇合，但一个售后始终只有一个活动节点。
- 每个节点只能使用 `end`、`default`、`single_select` 或 `manual` 一种后续模式。条件选项必须明确指向节点或结束；人工开启必须指向实际节点，人工跳过可指向另一个节点或结束，且开启与跳过目标不得相同。
- 字段联动只允许依赖同一节点中前置的一个父单选字段，但可多层级联；支持按父选项控制显示和子单选候选项。隐藏字段不保存、不检索，切换分支时清空失效字段；节点凭证不随字段切换删除。
- 发起人通过独立布尔标记加入固定处理人列表，创建时合并去重并固化；审核人规则保持不变，解析后处理人与审核人有交集则拒绝创建。
- 路线解析只读取最终通过字段快照，并在节点完成事务中原子激活唯一后续节点。人工决定沿用目标候选处理人、首个成功事务生效和独立决定计时。
- 未进入路线的节点不参与待办、提醒、日历、检索、分享、统计或处理时长。新版分支售后进行中不显示可能倒退的百分比。
- 新功能隔离验收后执行受控业务数据重置：保留账号、凭据、微信绑定、安全配置、编号计数器和脱敏审计；清理模板、售后、反馈、审核、凭证及 COS 对象、通知、分享、检索、统计和相关派生状态。不可恢复删除前必须再次核对精确目标、备份和费用影响并取得确认。

完整交互、状态机、安全边界、重置和验收规格见 `docs/superpowers/specs/2026-09-03-branching-workflow-and-conditional-fields-design.md`。

## Consequences

- 模板域、定义摘要、创建快照、完成事务、人工决定、字段校验、小程序模板编辑与节点填写均需升级。
- 通知、提醒、日历、检索、分享、运营统计和凭证保留必须统一识别实际路线，不能继续用节点顺序或 `optional_tail` 特例推断。
- 旧业务不迁移；正式重置后只创建流程模式版本 2 模板。重置前代码过渡期仍需失败关闭地读取现有数据。
- 不增加外部付费服务。若实现发现必须新增收费资源、扩大配额或改变权限，必须暂停并由项目所有者确认。
- 正式清理完成后不能直接回滚到只支持线性流程的旧版本，只能从完整备份恢复或前向修复。
