# ADR-0017：检索请求驱动的有界索引恢复

## Status（状态）

2026-09-10 接受；实现和部署验收进度见 STATUS.md。本决策补充 ADR-0012 的恢复触发方式，不改变授权、当前快照或可信 Timer 的清理边界。

## Context（背景）

真实已完成售后存在来源版本已推进、生成版本仍为零的待生成索引。仅部署快照修复不会恢复这些售后；旧版已生成但漏内容的代际也会被普通来源版本幂等检查跳过。默认 Timer 未启用时，查询会把尚未生成的记录静默当成无匹配。

## Decision（决策）

- 编号支持任意单字符与连续子串，节点名称、字段名称和值同样按规范化子串检索；不新建模板编号体系，不引入模糊语义匹配。
- 关键词查询通过现有受保护 API 与一次性 query 票据触发恢复预检，每个请求至多扫描 40 条售后头、重建 2 条可见且符合筛选的售后。只读取经过当前账号授权的内容，不为了命中而改反馈、审核、业务版本或完成状态。
- 需恢复的候选包括待生成、严格可初始化的旧记录以及旧索引格式。完整建代成功后记录 `searchSchemaVersion: 2`，来源版本相同但格式旧的代际不能直接幂等跳过。
- 对确由旧版静态模板和反馈协议产生的节点，允许读取没有处理轮次的元数据及最新已发布反馈；新版工作流标记存在但损坏时不得降级为旧格式。旧反馈必须与最新指针、修订、节点及售后归属一致，附件逐条验证归属、发布状态和认领数量；不补造轮次或动作，不把旧修订内容合并成虚构的当前轮。
- 历史售后头已有合法来源版本而未触碰节点完全没有检索派生属性时，允许受保护恢复补齐缺失节点的派生元数据。必须重新校验当前账号、售后来源版本、节点归属和并发版本；部分属性存在但不合法不是“完全缺失”，不得覆盖修复。正常快照和完整代发布校验仍必须通过。
- 使用现有查询 `cursor` 承载独立签名的恢复进度，绑定账号、权限模式、关键词、筛选和有效期；不接受客户端任意目标、版本或无签名跳过恢复。普通结果分页不重复全量恢复。
- 恢复中返回 `indexStatus: recovering` 与可续游标，客户端显示进度并有界自动继续。失败隔离到单条并保留 `incomplete` 信号，不得把不完整结果标成没有匹配或全部匹配；条件变化、页面隐藏或账号改变后停止续请求并丢弃旧结果。
- 请求恢复不执行旧代清理、不启用 Timer、不改变费用配置或数据库权限。原有可信 Timer 的周期回填、恢复、清理入口保持独立且默认关闭。
- 失败诊断仅输出固定操作、阶段和白名单错误码，不输出记录标识、字段正文、关键词、票据、异常消息或堆栈。

## Consequences（后果）

- 第一次检索可能包含旧数据补建时间；后续当前格式索引不重复建代。该成本通过有界请求和可见进度控制，不能宣称首次回填已实现低延迟。
- 不引入新集合、密钥或定时器；派生状态可从权威当前快照重建。回滚代码不需要回滚售后内容。
- 单字符、已完成字段、旧代恢复、空草稿、撤权、跨账号游标、失败部分结果与前端续请求都需回归验证；本地通过不能代替云端原始问题验收。
