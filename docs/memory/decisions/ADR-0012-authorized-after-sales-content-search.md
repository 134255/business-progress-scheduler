# ADR-0012：授权范围内的售后当前快照检索

## Status（状态）

已于 2026-08-25 接受；生产实现、CloudBase 部署和真实多账号验收尚未完成。

## Context（背景）

现有售后列表只按售后名称和编号做运行时子串匹配，无法按任一节点的动态字段、处理说明、审核意见或凭证文件名找到售后。直接扫描反馈、审核和凭证集合会产生无界读取，容易混入旧驳回轮次和被替换修订，也难以在查询期间撤权时阻止信息旁路。

CloudBase 同时存在 100 次事务文档操作上限和保守索引键预算；动态字段与用户文本没有足够小的统一长度上限，因此不能把所有内容拼接为单个数组索引或在请求时全库扫描。

## Decision（决策）

- 新增独立 `businessSearch` 云函数以及仅云函数读写的 `business_search_documents`、`business_search_requests` 集合。
- 将售后名称/编号/说明、节点名称/编号、动态字段名称和值、处理说明、当前审核意见和凭证文件名拆成版本化安全条目；长文本有界分段，令牌按独立 HMAC 密钥生成并按真实 BSON 结构保持在保守 768 字节索引预算内。
- 倒排令牌只产生候选，最终必须对规范化可见文本做连续子串校验。查询允许单字符，最多 5 个空格分隔关键词，多个关键词必须同时命中同一售后但可以分布在不同节点或字段。
- 只索引当前有效最新快照：处理中使用当前轮最新已发布进度，待审核使用当前活动审核轮和投票，已完成使用最终通过轮次；旧驳回轮、旧修订和被替换内容不参与命中。
- 所有改变当前检索内容的权威事务同步推进检索来源版本并标记待生成；事务提交后使用至少 192 位随机一次性内部票据调用工作器。新代完整写入并再次复核来源版本后才能原子发布，旧代和部分代永不参与查询。
- 业务变化提交后若索引生成失败，不回滚权威数据；相同请求重试只能恢复索引且不得重复反馈、审核、审计、通知或其他业务副作用。
- 活动 `super_admin` 可以查看和检索全部非创建中、非已删除售后。普通活动账号仍只限原有关系可见售后。每条候选在返回前重新读取当前账号和售后关系；撤权、停用、降权、缺失、损坏和版本过期统一按无结果处理，不暴露存在性。
- 历史回填和失败恢复只接受可信 Timer，使用最多 40 条原始候选的版本化 keyset 游标；不使用 `skip`，全失效页仍推进，损坏游标失败关闭。默认部署保持 `triggers: []`，正式周期另行批准。
- 原始关键词、字段内容、凭证名称、云路径、请求票据和账号标识不得写入日志或项目记忆。

## Consequences（后果）

- 部署需要新增两个集合、真实查询所需组合索引、`BUSINESS_SEARCH_HMAC_SECRET` 和独立云函数；旧版应用会忽略新增版本字段。
- 所有售后内容写入口都要接入索引版本和可恢复幂等编排，并用真实操作计数证明事务不超过 100 次。
- 搜索接口不提供精确全局总数；分页使用与账号、权限和筛选条件绑定的安全游标。
- 历史售后在回填完成前不能依赖部分索引；名称和编号可暂时走原授权路径，其他内容待当前完整代发布后才可命中。
- 真实 CloudBase 索引选择、代际并发、一次性票据、历史回填、超级管理员降权和普通账号存在性隔离必须单独人工验收。

完整规则见 `docs/superpowers/specs/2026-08-25-authorized-after-sales-content-search-design.md`。
