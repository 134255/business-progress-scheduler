# ADR-0004：业务冻结、驳回与审计修订预约

## Status（状态）

已于 2026-08-10 接受。

## Context（背景）

业务线需要支持上一节点驳回、受控关闭以及冻结后的审计式修订。普通业务凭证的 60 天保留期由业务线统一管理，但超级管理员可能在业务冻结后追加任意数量的修订附件。这些附件必须从各自上传时间起独立保留 60 个自然日，同时仍受单次修订附件总量不超过 20 MB 的约束。

CloudBase 单个事务最多允许 100 次文档操作，因此不能在一次事务中安全认领数量不受业务规则限制的修订附件。修订过程中还可能发生函数中断、并发重试、账号停用或业务版本变化，不能因此发布部分修订或暴露未完成的附件。

## Decision（决策）

- 当前活动节点负责人只能驳回序号紧邻的上一已完成节点。驳回事务重新读取当前账号、业务线和两个节点，校验当前指针、负责人、状态及两个节点版本；上一节点恢复为 `in_progress`，当前节点返回 `waiting`，但原到期时间、激活时间、完成时间、反馈版本和凭证均不重置。
- 业务线从 `active` 进入 `completed`、`cancelled`、`closed` 或 `deleted` 后视为冻结。普通元数据更新、反馈提交和旧版删除入口不得再修改冻结数据。关闭、取消和逻辑删除由业务线管理员或超级管理员执行，并在业务线上记录统一的 60 个自然日凭证清理期限。
- 冻结业务只允许超级管理员通过专用审计修订接口修改白名单字段：名称、说明、计划开始日期、计划完成日期和冻结终态。每次修订必须提供原因和准确版本，并保存修改字段的前值、后值、操作人、时间和最终结果；原节点与反馈历史永久不变。
- 审计修订使用确定性 `audit_logs` 预约记录，编号由业务线编号和下一版本号组成。预约只保存安全摘要、计数、累计字节数、游标摘要和租约，不保存原始请求键，也不保存无界附件编号数组。
- 修订附件按固定编号分块认领，每块最多 40 个文件，使账号、业务线、预约、附件读取与更新的总操作数保持在 100 以内。所有附件总量仍严格限制为 20 MB，但不增加文件数量上限。
- 每个修订附件从自身 `uploadedAt` 起计算 60 个自然日，写入 `retentionScope: evidence` 与 `retentionSource: audit_amendment`。只有修订预约进入 `published` 后，业务成员或超级管理员才能获得临时访问地址。
- 同一修订并发重试必须返回同一个已发布结果；不同内容占用同一业务版本时返回 `VERSION_CONFLICT`。每个分块和最终发布事务都重新读取当前有效超级管理员与冻结业务版本。
- 旧业务写入、删除和反馈写入处理函数不再进入部署路由。兼容性仅保留必要的旧数据读取，不允许通过旧入口绕过编号、冻结、审计或权限规则。

## Consequences（后果）

- `audit_logs` 和 `evidences` 增加内部预约、认领、摘要、租约及回滚字段，这些字段不得直接返回给小程序页面。
- Task 11 必须先扫描已过期且未发布的审计修订预约，再处理孤儿附件清理。对于 `reserved` 预约，需要分块恢复附件原 `orphanExpiresAt`，清除修订认领与保留期字段，并把预约安全终结为不可发布状态；不得回收租约仍有效或已经发布的修订。
- Task 11 回收必须使用确定性编号、严格关系校验和幂等状态转换，避免与正在继续的修订重试竞争后误删附件。
- Task 10 的超级管理员修订页面只能展示受保护接口返回的安全投影；冻结业务的全局管理员检索与详情入口仍需在客户端集成阶段补齐并验证。
- CloudBase 真机并发重试、目标环境索引、云函数部署和微信开发者工具验收仍属于独立的人工验证边界。
