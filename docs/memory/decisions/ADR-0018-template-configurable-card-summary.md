# ADR-0018：独立模板展示配置与版本化卡片摘要

## Status（状态）

2026-09-10 设计已接受；本地实现、任务/整项审查及最终修复复审完成。代码已提交，businessApi已部署并回读核对65/65生产及包文件一致；用户截图确认客户端代码上传，但展示配置加载仍待部署后复验，体验版指向及真实设备验收仍unverified。具体证据及阻断见STATUS。

## Context（背景）

售后卡片需要显示一次编号和模板选择的部分字段。展示配置修改应影响该模板已有及新建的售后，不能修改历史流程定义或业务内容；同时须避免列表逐条加载全历史反馈造成响应变慢。

## Decision（决策）

- 模板新增独立 `cardDisplay` 修订号，保存最多4个节点/字段稳定标识，不接受业务值或任意读取路径。活动超级管理员可在流程启用时单独编辑展示配置，不改变流程 `version`、定义摘要或节点清单。
- 首页及列表在授权、筛选、分页后共用摘要逻辑，只读取所选节点当前有效的已发布反馈或审核快照。按实例字段定义解释历史值，隐藏条件或未进入路线的旧值不展示。
- `business_lines.cardSummary` 仅为绑定模板配置和业务来源版本的派生缓存，不改业务状态、版本、更新时间或检索状态。缓存命中仍须当前账号与业务权限核验；源数据变化或配置变化时只按需重建当前页，保存成功后的派生刷新失败不能推翻原业务成功。
- 现有全局列表允许超级管理员看到非成员售后的固定信息，但普通详情字段要求成员资格。卡片保留该边界：没有字段读取权时不输出摘要值，也不让单条摘要权限差异破坏原有全局列表。
- 空配置正常返回固定卡片信息；来源无法映射或损坏返回可重试的摘要不可用状态，不能伪装未填写或永久待生成。旧客户端/服务端组合保留安全回退。
- 采用请求内去重、最多4路并发和固定文档事务；不遍历全库或反馈/附件历史，不增加云函数、集合、Timer 或外部服务。

## Consequences（后果）

- 修改配置在各入口下一次成功刷新生效，不是实时推送。配置刚变化的首次读取有额外重建成本，必须区分缓存命中与冷读测量；本地测试耗时不能代表真机延迟。
- 展示规则独立于历史流程快照，删除仍被展示配置引用的模板节点/字段须先调整配置；不会静默改变历史客户数据。
- 摘要值属于客户数据，不进入日志、Git、项目记忆或客户端长期存储。派生缓存不是权威或恢复来源。
- 新卡片布局与配置编辑器需要新客户端包。云端部署和客户端发布须分别验证，不继承旧故障修复的部署授权。
