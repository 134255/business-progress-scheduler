# ADR-0006：索引预算、历史显示快照与保留游标

## Status（状态）

已于 2026-08-12 接受。

## Context（背景）

CloudBase 公布单个索引键上限为 1024 字节，但没有公布数组多键索引与 BSON 的逐字节实现公式。账号角色数组和通知受众若只按人数限制，30 个真实长度账号已可形成约 1161—1201 字节的索引值。审核详情若实时读取全部历史参与账号，则账号停用会使历史不可读，改名会改写历史显示。保留工作器使用全表读取加 `skip`，返回数虽然受限，实际扫描量仍无界。

## Decision（决策）

- 对 `managerUserIds`、`memberUserIds`、节点角色、轮次审核人和 `recipientUserIds` 统一执行保守索引键预算：每数组最多 50 项，可见 BSON string-array 编码最多 768 字节；业务成员还为创建者预留一个最长 128 字节账号位。模板验证、启用、普通可用性、业务创建及通知写入必须使用同一边界，错误为“索引账号数组最多 50 人，保守 BSON 预算不超过 768 字节”。
- 该预算与事务 100 次硬上限独立且同时生效；任何一个先超限都在事务前失败关闭。由于官方模型未公开，真实 CloudBase 索引创建和隔离写入仍属于未验证部署边界。
- 新审核轮次在创建事务中读取当时活动的处理人和审核人，并固化受控显示名数组。详情查询只重新授权当前调用账号，不再要求所有历史参与账号仍活动。缺少快照的旧轮次仅显示固定的“历史处理人/历史审核人”占位，不实时回填、不返回账号编号或 OpenID。
- `evidenceRetention` 使用 `system_settings/evidence-retention:*` 保存阶段、类型化序列化的 `afterSortValue` 与 `afterId`。每个阶段声明与权威查询及部署索引一致的排序字段：范围阶段按其到期/租约字段升序再按 `_id` 升序，固定状态阶段按状态字段升序再按 `_id` 升序。CloudBase 单查询不依赖元组 OR；续页以“同排序值且 `_id` 更大”和“排序值更大”两段有界查询实现严格元组后继，两段合计原始扫描不超过 40，不使用 `skip` 或全量读取。游标字段缺失、类型错误或不可严格反序列化均失败关闭；页尾阶段轮转和回绕保证坏记录之后的候选可达，并允许崩溃后的幂等重交付。
- 纯旧 OpenID 冻结业务的保留提醒只写 `audienceRole: super_admin`，绝不把 OpenID 写入通知。已存在的同确定性编号空受众通知在事务中升级为该角色受众；账号制关系损坏或超预算时不得借此降级。

## Consequences（后果）

- 角色可配置人数取“50 项、768 字节、成员预留创建者、100 次事务”四者的最小值，不再承诺接近 100 人的数组角色。
- 部署前必须创建手册逐项列出的状态前缀、权威排序字段和 `_id` 组合索引；真实 CloudBase 对两段范围 keyset 查询的复合索引选择必须单独验收。
- 历史显示稳定且不会因停用失败，但旧轮次的真实历史姓名不可无审计地推断或回填。
- 保留游标文档属于运行状态，不得由操作员手工伪造、删除或覆盖；工作器仍保持 `triggers: []`，直到另行批准。
