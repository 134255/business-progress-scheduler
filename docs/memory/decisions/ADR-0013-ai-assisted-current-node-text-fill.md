# ADR-0013：AI 辅助当前节点文本识别与字段预填

## Status（状态）

已于 2026-08-26 接受设计，生产实现已于 2026-08-27 推送并完成首轮 CloudBase 部署；真实模型端到端验收尚未完成。

## Context（背景）

处理人需要把微信或其他来源的一段半结构化文本重复录入当前节点的动态字段。纯规则解析难以覆盖自由文本、字段别名、日期和选项表达；直接让小程序调用模型又会绕过当前账号、售后、节点、版本和字段定义授权，并可能把云函数变成公共 AI 代理。

原始粘贴文本可能包含客户内容，因此不能为了幂等、调试或检索而长期保存，也不能写入日志、审计、通知、运营事实或项目记忆。

## Decision（决策）

- 小程序只通过 `businessApi.recognizeNodeText` 主动发起识别；入口重新校验活动处理人、当前售后节点、节点状态、版本和字段定义，客户端身份、模型、提示词、字段定义和阈值全部剥离。
- 新增独立 `nodeTextParser`，默认使用目标环境已启用且无需购买标准版的 CloudBase AI+ `hy3` 托管模型，并保留只允许服务端环境变量覆盖的模型适配器；小程序不能直接把普通事件当作授权调用解析工作器。
- `businessApi` 为每次批准调用签发五分钟、单次消费、至少 192 位随机的一次性内部票据，绑定账号、售后、节点、版本、字段定义摘要、原文摘要和请求键摘要。票据只存摘要和状态，不存原文或模型结果。
- 新增 `node_text_parse_requests` 和 `node_text_parse_usage` 两个仅云函数读写集合；后者按账号摘要保存分钟/日计数和单飞锁，限制每分钟 10 次、每个上海自然日默认 300 次且同账号只有一个在途请求。每日额度可由仅服务端可见的 `NODE_TEXT_PARSE_DAILY_LIMIT` 在 `1..1000` 范围内调整；缺失使用 300，损坏配置失败关闭，客户端不能覆盖。
- 模型只接收本次原文和当前节点规范化字段定义；不接收账号、售后元数据、其他节点、反馈历史、审核、凭证或永久文件编号。原文和结果不持久化、不记录日志。
- AI 只返回候选，客户端必须展示预览。已有字段默认不覆盖，用户应用后仍需经过既有保存或提交入口。
- 单选、多选只能匹配现有选项：精确匹配优先；模糊语义匹配阈值为 0.5，分数高者优先；单选前两名过近时人工确认，多选按分数展示，模型不能创造选项。
- 账号、页面、节点版本、字段定义或本地表单在请求期间发生变化时，迟到结果丢弃；模型返回后服务端再次授权。
- 第一版 `nodeTextParser` 保持 `triggers: []`。过期票据通过有界机会式清理处理，不新增定时工作器。

## Consequences（后果）

- 需要新增云函数、两个集合、一条到期索引以及 CloudBase AI+ 模型/配额/费用告警配置；`businessApi` 和小程序也需重新部署。
- 一次性票据增加了事务和部署复杂度，但阻止直接调用、重放、摘要替换和无限模型费用消耗；票据不是用户可见业务数据。
- 为避免保存原文和模型结果，响应丢失后的重试可能再次消耗模型额度；分钟/日限流提供成本上界。默认每日 300 次是当前运营起点，后续可依据真实使用量、Token 成本和平台配额调整而不改变客户端协议。
- 模型分数是匹配置信度而非校准概率，所有候选仍需用户确认，不能宣称 50% 阈值代表真实正确率。
- `hy3` 足以承担当前中文字段抽取、日期规范化和受限选项匹配；若未来真实质量或成本证据支持更换模型，只调整服务端模型配置或受测试保护的默认值，不改变客户端、票据或字段校验协议。
- 真实模型可用性、Token 消耗、函数延迟、嵌套调用、集合权限、索引和真机交互必须在目标 CloudBase 单独验收。

完整规则见 `docs/superpowers/specs/2026-08-26-node-text-smart-fill-design.md`。
