# ADR-0010：运营统计采用派生事实与每日汇总

## Status

已接受并已本地实现；真实 CloudBase 部署、索引和多账号验收尚未验证。

## Context

现有运营接口按审核轮次提供个人工时明细。直接在每次打开页面时扫描全部业务、轮次和投票无法稳定支持最长 366 天、模板版本、稳定节点、实际参与人员及日/周/月趋势筛选。只保存每日总数又无法提供业务下钻、精确样本口径和参与人员筛选。

## Decision

- 当前业务、节点、审核轮次和投票继续作为权威来源。
- 节点和业务完成后生成确定性的派生统计事实，并按上海自然日维护确定性每日汇总。
- 主图组合每日汇总；明细下钻读取事实样本并重新执行当前业务权限校验。
- 所有活动账号可以查看全局汇总；普通账号只能下钻原本有权查看的业务，超级管理员可以下钻全部业务并保留 CSV 导出权限。
- 节点处理样本累计全部处理轮；审核主指标累计各终态审核轮从提交到最终决定的完整工作分钟。个人响应分钟只用于实际投票人明细。
- `pending_calendar` 不作为零值；历史缺字段不推测。
- 新增只信任平台 Timer 的 `operationsAnalytics` 工作器，以固定批量、持久游标和幂等事务生成事实与汇总。

## Consequences

- 需要新增 `operations_analytics_facts`、`operations_analytics_daily`、组合索引和独立云函数。
- 业务流转不能依赖统计生成成功；需要待生成状态和后台恢复。
- 汇总查询保持有界，但精确中位数在样本超过安全上限时必须要求缩小范围。
- 真实部署先保持触发器为空，并通过一次性 Timer 和多账号权限验收后再单独决定计划任务。
- 现有 `calendarSync`、`workflowReminder`、`evidenceRetention` 职责和触发器策略不变。
